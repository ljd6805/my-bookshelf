  • 장 구조: 모든 장에 “앞 장 떠올리기”(1장 제외), 본문 4문단(두 문단에서 넓힘: 손으로 따라 하는 계산 한 문단과 한계·실제 쓰임 한 문단), 실험마다 “먼저 예측하기”, 실험 뒤 “해결한 것과 남은 질문”을 둡니다. 장 끝 질문은 본문 문단에서 “남은 질문” 칸으로 옮겼습니다.
  • 따라가는 양: 9장 질문의 근거 사슬(마리 퀴리 —발견→ 폴로늄, 이렌 —자녀→ 마리 퀴리, 이렌 —수상→ 1935 화학상)을 모든 장의 같은 자리에 같은 표시(주황 고리와 굵은 선)로 그리고, 장마다 그 사슬에 무슨 일이 일어나는지 한 문장으로 적습니다(docs/08#one-quantity).
  • 새 실험 두 개: 2장 “인접 행렬을 거듭제곱해 보행 수 세기”(A², 대각선 = 차수, 처음 0이 아닌 k = 최단거리), 4장 “그래프 전체를 관계 규칙으로 검사하기”(검사 방식 위반과 RDFS 결론을 나란히, 종류 없는 새 점 브로니스와바). 둘 다 실제 계산이며 js/graph.js의 walks·shapeReport가 맡습니다.

03 실험과 확인 수준

02 walk실험 1: “폴로늄에서 1·2·3걸음 안에 닿는 점은 각각 몇 개”. 첫째 문단이 1걸음(마리·피에르·폴란드, 3개)만 말하고 9·13은 말하지 않아 예측할 거리가 남는다. 다만 책 첫 화면의 걸음 위젯이 1·2·3걸음의 결과를 먼저 보여 준다. 실험 2: “3걸음 보행은 몇 가지, 4걸음이면 늘까”. 질문 속 힌트(“마리를 거치는 길과 피에르를 거치는 길”)가 3걸음 답 2를 거의 말해 주지만 4걸음은 열려 있다.실험 1: 3개·사실 4 / 9개·16 / 13개·21, 3걸음에서 사슬 세 사실이 나열된다. 실험 2(새 실험): 막대 목록 “A³의 폴로늄 행”에서 ▶ 표시가 붙은 1935 화학상 칸이 2걸음 0, 3걸음 2, 4걸음 6이고 합계는 16·56·269다. 마리→마리 2걸음은 8로 마리의 간선 수와 같다. 막대와 아래 요약 상자(“BFS 최단거리 3걸음 · 보행 수가 처음 0보다 커지는 걸음 수 3걸음 → 두 값이 같습니다”)가 있어 행렬을 몰라도 읽을 수 있었다. 결과 읽기의 “4걸음 6개 중 2개는 프레데리크를 거치고 4개는 배우자 간선이나 파리를 거쳐”는 실험이 경로를 보여 주지 않아 확인할 수 없다. A가 방향을 무시한 대칭 표라는 말이 본문에 없어, 방향 있는 관계에 익숙한 독자는 “이렌 —자녀→ 마리”가 거꾸로도 세어지는지 잠깐 헷갈린다.실험 2는 이해할 수 있음. 확인할 수 없는 경로 설명 → 리안·나래(사소). “A는 방향을 무시해 양쪽 칸에 같은 수를 적는다” 한 줄 → 나래(사소). 1280px에서 막대 이름 “1935 화학상”, “1903 물리학상”이 두 줄로 꺾인다 → 리안(사소). 첫 화면 위젯과 예측의 겹침 → 지안(사소).

Curie”가 이미 보인다.0.15 → 묶음 3, 섞인 묶음 2. 0.7 → 묶음 9, 섞임 0, 갈라진 인물 3. 식별자 → 묶음 3, 섞임 0. 결과 읽기는 “0.5에서 M. Curie와 P. Curie(J 0.67)가 붙는다”고 하는데, 결과 문장의 J 목록에 이 쌍이 없어 0.67을 실험에서 볼 수 없었다(고침). 직접 해 보기(“마리 퀴리”와 “Marie Curie”를 묶는 문턱)는 슬라이더 최솟값 0.1에서도 따로 남아 “없다”를 확인할 수 있다.처음 상태가 예측 설정과 같음(공통 1) → 지안·리안. J 목록에 M. Curie–P. Curie 쌍 추가 → 이번 리허설에서 고침(js/labs-structure.js).
04 ontology실험 1: “수상→파리를 검사 방식과 RDFS 방식에 넣으면”. 다섯째 문단(“RDFS에서 이 규칙은 오류를 막는 대신 새 사실을 만들어 낸다”)과 식 아래 설명으로 추론해야 하는 질문이라 좋다. 실험 2: “종류 없는 브로니스와바를 넣으면 두 방식은 무엇을 내놓고, 맞는 정보일까”. 다섯째 문단의 “종류를 모르는 점에는 쓸모 있는 결론”이 RDFS 쪽 답을 반쯤 준다.실험 1: 맞는 트리플 통과, 목적어 위반 “파리는 상의 하위 종류가 아닙니다”, RDFS “파리는 ‘상’이라고 결론”. 실험 2(새 실험): 21개만 → 위반 0·결론 0, 수상→파리 → 위반 1·“+ 파리는 상”, 브로니스와바 → 위반 1(종류 없음)·“+ 브로니스와바는 사람”, 세 개 모두 → 위반 3·결론 3. 검사 방식과 RDFS 방식이 한 상자에 위아래로 나란히 있고, 요약 상자가 “사실 24개 … 통과 21개 · 검사 위반 3개 · RDFS 새 결론 3개”로 세어 주어 처음 읽어도 이해했다. 결론 셋 가운데 어느 것이 맞는지는 표시하지 않는데, 그것이 직접 해 보기의 과제라 괜찮다.실험 2는 이해할 수 있음. 걸린 곳 없음.
05 reasoning“위치 규칙 하나만 켜면 1·2라운드에 새 사실 몇 개”. 그림 5-1은 마리 한 사람만 다뤄 답을 다 주지는 않는다. 하지만 실험이 처음부터 위치 규칙·1라운드로 열려 결과 “1라운드 · 5개”가 예측 칸 바로 아래 보인다. 개념 문단과 식은 규칙을 (x 태어난 곳 c) ∧ (c 속한 곳 k) ⇒ (x 태어난 곳 k) 하나로만 적어서, 식대로 예측한 독자는 1라운드를 3개(세 사람의 나라)로 답하게 된다.위치 1라운드 5개(세 사람의 나라 + “파리 —속한 곳→ 유럽”, “바르샤바 —속한 곳→ 유럽”), 2라운드 3개, 고정점. 세 규칙 → 9개·3개, 23 → 35개. 결과 사실 다섯 가운데 둘은 “속한 곳”이 이어지는 규칙에서 나왔는데, 본문과 식 어디에도 그 규칙 꼴이 없어 “왜 태어난 곳 규칙이 속한 곳 사실을 만들지?”에서 멈췄다. 확인 문제 보기 “1번 · 2번”은 보기 번호(1. 2.)와 겹쳐 헷갈렸다(고침).식·본문과 실험 결과의 어긋남 → 나래(js/content.js reasoning 문단·식 설명에 “같은 규칙이 (c 속한 곳 k) ∧ (k 속한 곳 m) ⇒ (c 속한 곳 m)에도 적용된다”). 처음 상태가 예측 설정과 같음(공통 1) → 지안·리안. 보기 “1번·2번”을 “한 번·두 번”으로 → 이번 리허설에서 고침.
06 query“두 줄 패턴의 답은 몇 줄, 추론을 포함하면 달라질까”. 그림 6-1 설명이 “답은 ?x = 마리 퀴리, ?y = 피에르 퀴리 한 쌍”이라고 먼저 말하고, 실험도 처음부터 그 두 줄·적힌 사실만으로 열려 “답 1줄”이 보인다. 추론을 포함했을 때의 답은 본문이 말하지 않아 그 절반만 예측할 거리가 남는다.발견한 사람 → 2줄, 배우자 더함 → 1줄, 추론 포함 → 2줄(사실 35개). SPARQL 글상자가 조립한 패턴을 보여 주어 SQL의 JOIN을 아는 독자에게는 쉽게 읽혔다. “같은 변수(?x)는 모든 줄에서 같은 값이어야 하므로 줄을 더할수록 답은 줄거나 그대로”는 추론 포함일 때 1줄 → 2줄로 늘어나는 것과 함께 보면 잠깐 모순처럼 읽히는데, 그래프가 바뀐 것이라 맞는 말이다.예측 답이 먼저 보임(공통 1) → 지안·나래(그림 설명). 위 문장에 “같은 그래프에서는”을 붙일지 → 리안(사소).
07 extraction“문턱을 0.30 → 0.50 → 0.85로 올리면 정밀도와 재현율은 오를까 내릴까”. 둘째 문단이 “문턱을 높이면 틀린 사실은 줄지만 맞는 사실도 놓친다”고 방향을 먼저 말한다. 숫자는 0.60의 값만 본문에 있어 크기는 예측할 거리가 남는다.0.30 → 정밀도 75.0%·재현율 100%·F1 0.857, 0.50 → 88.9%·88.9%·0.889, 0.85 → 100%·33.3%·0.500, 초기화 0.60 → 87.5%·77.8%. 후보마다 “넣음 · 맞음 / 넣음 · 틀림 / 뺌 · 놓침 / 뺌 · 틀린 후보”가 글자로 붙어 색을 못 봐도 읽힌다. 직접 해 보기(F1이 가장 큰 구간)는 0.01 간격 슬라이더로 찾을 수 있다.방향이 먼저 보임(공통 1, 작음) → 지안. 그 밖에 걸린 곳 없음.
08 embedding“화살표 0이면 바르샤바에서 가장 가까운 나라는 폴란드일까, 평균 화살표면 마드리드는 스페인을 고를까”. 본문은 r = (1.5, 1.2)일 때 바르샤바만 계산하고 r = 0과 마드리드는 말하지 않는다. 처음 읽는 사람은 r = 0이면 폴란드라고 답하기 쉬운데 실제로는 스페인이라 틀려 볼 수 있는 좋은 질문이다.r = 0 → 바르샤바 + r에 가장 가까운 나라 스페인(0.67), 폴란드 5위, 맞힌 쌍 0/4. 학습된 화살표 → 4/4, 마드리드 → 스페인 1위(0.07). 틀린 방향 → 베를린에서 독일 5위, 1/4. 결과 읽기가 실험과 맞는다. 직접 해 보기(세로 0 → 1.2)는 0.05 간격이라 24번 움직여야 해서 조금 번거롭다.걸린 곳 없음(직접 해 보기 간격은 사소).
09 graphrag“문장 검색은 k가 몇이어야, 그래프는 몇 걸음, 그때 문맥 사실은 몇 개”. 3걸음은 앞 장 떠올리기와 그림 9-1이 말하지만 2장의 복습이라 괜찮다. k = 12와 문맥 21개·11개는 실험 전에는 어디에도 없다. 다만 “그때 문맥 사실”이 모든 관계일 때인지 관계를 좁혔을 때인지 질문만으로는 모호하다.처음(k 3, 2걸음) → 둘 다 근거 부족. 그래프 3걸음 → 문맥 21개 → 1935 화학상. 관계를 좁힌 3걸음 → 11개, “✓ 사슬 완성 마리 퀴리 → 이렌 → 1935 화학상”. 문장 12개 → 문장 검색도 답. 결과 읽기가 실험과 맞는다. 마지막 과제(“이렌 —자녀→” 두 사실이 빠졌다고 가정)는 실험에 사실을 빼는 조작이 없어 손으로 확인할 수 없고, 글로만 답해야 한다.마지막 과제를 실험으로 확인할 길(예: 사실 빼기 선택 상자)을 둘지, 글로 답하는 과제임을 밝힐지 → 지안·리안. 예측 질문의 “그때” → 지안(사소).

모든 장에 걸친 것

  1. 공통 1 · 몇몇 장은 예측 전에 답이 보입니다(중간). 결과 읽기 덮개는 아홉 장 모두 잘 닫혀 있습니다. 그런데 1장(개념 셋째 문단)과 6장(그림 6-1 설명)은 본문이 예측 질문의 답을 먼저 말하고, 3·5·6장은 실험이 처음부터 예측 질문의 설정으로 열려 예측 칸 바로 아래 결과가 보입니다. 2장 실험 2의 힌트와 7장 둘째 문단은 답의 절반을 줍니다. 2·4·8·9장은 본문이 말하지 않은 값을 묻거나 원리로 추론하게 해 예측 단계가 살아 있습니다. 처음 상태를 예측과 다른 설정(예: 3장 0.3, 5장 규칙 없음, 6장 패턴 한 줄)으로 열고, 1·6장은 질문을 본문이 말하지 않은 설정으로 바꾸는 방법이 있습니다 → 지안(방식), 리안·나래(반영).
  2. 공통 2 · 오답에도 정답 해설이 다 나옵니다(작음). 확인 문제와 전이 문항은 오답을 누르면 “다시 생각해 보세요.” 뒤에 정답의 이유가 그대로 붙습니다(js/app.js 43·44행). 1장 확인 문제는 오답 하나만 눌러도 “점은 늘지 않고”로 답이 나옵니다. 복습 퀴즈처럼 첫 오답에는 다시 보라는 안내만 줄지 지안이 정합니다. 「LoRA의 원리」 리허설의 공통 2와 같은 문제입니다.
  3. 공통 3 · 다음 장 이동 칸의 “이동 이유”가 다음 장의 질문입니다(작음). 예: 1장 끝 “이동 이유: 폴로늄에서 몇 걸음이면 1935년 노벨 화학상에 닿을까요?” 이유가 아니라 질문으로 읽힙니다. 각 장의 “남은 질문” 문장을 이유로 쓰면 이어집니다 → 리안·지안.
  4. 공통 4 · 표지의 실험 수가 책과 다릅니다(작음, 서가). 서가 표지 꼬리줄은 “9장 · 9개 실험”(data/catalog.json cover_meta)인데, 책 첫 화면은 “11 인터랙티브 실험”, 서가 펼친 화면 설명은 “9개 장과 11개 실험”이라 합니다. 실험 두 개를 새로 더한 뒤 cover_meta를 고치지 않은 것으로 보입니다 → 해원 또는 편집장, build_catalog.py로 다시 생성.
