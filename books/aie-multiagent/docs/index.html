멀티 에이전트 · 제작 문서

「AI 엔지니어링 처음부터」 시리즈 17권 《멀티 에이전트 · 여럿이 나눠 맡고 서로 확인하기》의 기획, 원본 레슨 대응, 구현, 검증을 한곳에 모았습니다. 작성일은 2026-10-08입니다. 원본은 rohitg00/ai-engineering-from-scratch(MIT)의 Phase 16 · Multi-Agent & Swarms입니다. 원문과 코드를 옮기지 않았고, 개념과 순서만 참고해 새로 썼습니다.

1. 기획

  • 독자: 도구를 부르는 에이전트 하나는 만들어 봤지만, 여러 에이전트를 묶을 때 무엇을 얻고 무엇을 새로 잃는지 숫자로 따져 본 적은 없는 사람입니다. 반장과 조사원, 토론, A2A 같은 말은 들었어도 언제 나누지 말아야 하는지 설명하기 어려워합니다.
  • 끝의 행동: 멀티 에이전트 시스템에서 올라온 사고 보고 하나를 받으면, 그 원인을 어느 장의 변수에서 찾을지 고릅니다. 변수의 예는 공유 기억의 쓰기 권한, 재시도 횟수, 모델의 단일 문화입니다. 그다음 “에이전트를 더 붙이기”, “더 오래 돌리기”, “독립된 확인 붙이기” 가운데 어느 처방이 지표를 실제로 움직이는지 계산으로 확인하고, 아직 확인하지 못한 것을 적습니다.
  • 공통 사례: 시청 정책팀이 보고서 팀에 묻습니다. “공공자전거 대여소를 내년에 30곳 늘려야 할까?” 처음에는 에이전트 하나가 문서를 혼자 읽습니다. 장이 넘어갈 때마다 같은 팀이 반장, 조사원 가·나·다, 작성자, 비평가, 검증자로 나뉩니다. 팀은 메시지 약속과 차례 정하기, 대기열, 토론과 합의, 데이터 흥정과 몫 나누기를 차례로 겪습니다. 5장에서는 조사원 가가 원문의 “4.2% 증가”를 “42%”로 잘못 옮기고, 이 숫자는 8장의 합의 실험과 마지막 장의 사고 진단까지 이어집니다.
  • 이야기 방식: 이 책은 하나의 대상이 변하는 이야기입니다. 장마다 보고서 팀이 새 구조(메시지 봉투, 선택자, 반장, 검증자, 대기열, 투표, 집계 규칙, 제안 생성기, 마음 모형, 체크포인트)를 얻습니다. 그 구조로 앞 장에 남은 질문을 풀지만, 매번 새 실패도 하나씩 따라옵니다. 마지막 장은 시의회 보고 뒤에 올라온 사고 세 건에 처방을 고르게 합니다.
  • 범위: 원본 Phase 16의 레슨 25개 전부를 다룹니다. 다수결의 이항분포는 확률과 통계 책이 이미 깊게 다루고, 에이전트 고리의 큰 그림은 AI Book, 다중 에이전트 강화학습의 기초는 시리즈 10권 강화학습이 다룹니다. 그래서 이 내용은 한 문단으로 줄이고 cross 링크로 보냅니다. 대신 구현에서 갈리는 판단에 분량을 씁니다. 예를 들면 언제 나누지 말아야 하는지, 손넘김에서 단계가 빠지는 이유, 계층 깊이와 의미 흐림, 비평가와 검증자의 차이, 공유 기억의 쓰기 권한, 품질 문 없는 흔적 길잡이, 단일 문화, 값은 코드가 계산하는 흥정, 재시도 폭풍입니다.
  • 증거: 실험 16개는 모두 브라우저에서 실제로 계산합니다. 사용하는 계산은 다수결 확률(이항분포), 섀플리 값, 대기열 일정, A2A 상태 전이, 재시도 부하의 반복 계산입니다. 흥정, 개미 군집식 길잡이, 마음 모형은 시드를 고정한 시뮬레이션입니다. 문서 토큰 수, 걸리는 시간, 버그를 잡는 비율, 연합 가치표, 다섯 에이전트의 답과 자신감은 이 책이 정한 교육용 가정값이고, 결과 문장에서 따로 밝힙니다. 기억 오염 실험과 세 가지 공격은 미리 정한 시나리오입니다. 실제 LLM은 부르지 않습니다. 논문의 수치(성사율 26.67%→88.88%, MAST의 실패 분류 등)는 원본 커리큘럼 기준(확인일 2026-10-08)으로만 인용하고, 새 수치를 지어내지 않았습니다.

4. 검증

검증일은 2026-10-08입니다. 브라우저 안의 계산과 화면만 확인했습니다. 실제 LLM 에이전트, A2A 서버, 큐 시스템으로 확인하지는 않았습니다.

팩트·출처 검수: 이 책을 쓰지 않은 검수 에이전트가 2026-10-08에 사실·수치·실험·용어·출처를 검수하고 오류 9건을 고쳤습니다. 팩트·출처 검수 기록에서 발견과 수정, 확인하지 못한 것을 봅니다.

  • 계산 검사: npm test --prefix books/aie-multiagent를 통과했습니다(math 19개, routes 7개, 모두 26개). 확인한 값의 예는 다음과 같습니다.
    • 문서 7,000토큰이면 29개부터 창 200k를 넘습니다.
    • 끝 상태는 어떤 사건도 받지 않습니다.
    • 손넘김의 검토 도달은 p = 0.2에서 0.64입니다.
    • 조사원 띄우기 비용 1분에서 가장 빠른 K는 5(38분)입니다.
    • 충실도는 (1−e)^(2d)입니다.
    • 검사 결과 확률의 합은 1입니다.
    • 읽기 전용 검증자만 42%를 4.2%로 고칩니다.
    • 대기열 일정은 하한 아래로 내려가지 않습니다.
    • 품질 문이 있으면 가장 좋은 배정을 찾습니다.
    • ρ = 1이면 투표자 한 명과 같습니다.
    • 동조 공격에서는 자신감 가중만 맞습니다.
    • 섀플리 값의 합은 전체 가치와 같습니다.
    • 1차 마음 모형은 겹침을 줄입니다.
    • 차단기는 부하를 1로 묶습니다.
    • 독립된 확인만 사고 세 건을 모두 고칩니다.
  • 예제 키: lab-guides.js의 예제 48개가 쓰는 입력 이름이 모두 실제 input·select의 id와 같습니다. 브라우저 검사가 예제 버튼을 모두 눌러 확인했습니다.
  • 브라우저 검사: tests/browser.cjs로 1280·390·320px에서 다음을 확인했습니다. 결과는 evidence/browser-results.json에 있습니다(화면 42개, 실험 확인 48번, 콘솔 오류 0).
    • 표지와 12장을 엽니다.
    • 실험 16개마다 예제 버튼, 입력 최솟값과 최댓값, 선택 상자의 모든 값, 초기화를 누릅니다. 결과 문장에 NaN이나 undefined가 없어야 합니다.
    • 확인 문제의 정답과 오답 반응을 봅니다.
    • 가로 넘침이 없는지 봅니다.
    • 서가로 버튼과 목차 열고 닫기를 확인합니다.
  • 눈으로 확인: 표지, 1장 그림, 320px 실험 스크린숏과 그림 12개를 열어 글자 겹침, 잘림, 빈 그림이 없는지 봤습니다. 9장과 10장 그림은 이 확인에서 글자 겹침과 선 배치를 고쳤습니다. 표지 그림은 check_cover.py를 통과했고, 서가 삽화에는 @keyframes와 동작 줄이기 두 규칙이 있습니다.
