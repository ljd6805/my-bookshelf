교육 모형과 검산 기준

화면 실험은 JavaScript의 합성 데이터와 명시된 시나리오를 사용한다. Prisma 엔진·SQL 실행·벤치마크라고 표시하지 않는다. 실제 Prisma 실행은 examples 폴더의 별도 로컬 실습이다.

  • 상태가 TODO/DONE/TODO인 작업 세 개에서 DONE 필터 결과는 한 개. 정렬·필터·선택 필드의 변화를 구분한다.
  • Project 1에 Task 두 개, Project 2에 Task 한 개가 연결되면 프로젝트 1의 관계 조회 결과는 두 개. every는 자식 0개인 경우에도 참이라는 조건을 설명한다.
  • 첫 쓰기 뒤 둘째 쓰기 실패 시 개별 쓰기는 첫 변경이 남고 transaction은 모두 취소되는 시나리오로 비교한다. 외부 시스템 부작용과 동시성은 이 모형에서 실행하지 않는다.
  • N개 부모를 한 번 조회한 뒤 자식 조회를 N번 별도 실행하는 고정 계획은 1+N회. 묶어서 부모와 자식을 각 한 번 읽는 계획은 2회. 실제 Prisma 최적화·DB·로딩 전략에 따라 달라진다.
  • 페이지 크기 10, offset 20이면 단순 순차 모형에서 30행을 지나 10행을 선택한다. 인덱스가 있는 cursor 비용은 DB 실행계획을 측정해야 한다.

오해와 제외 범위

타입 안전 ≠ 입력 검증·접근 권한. generate ≠ DB 스키마 적용. transaction ≠ 외부 API 롤백. include ≠ SQL 한 번 보장. SQLite 통과 ≠ PostgreSQL 동시성 검증. Prisma Postgres 유료 서비스 가입은 실습에 필요하지 않다.

고급 쿼리 플래너, DB 이식 자동화, Prisma 8 전환 실습, MongoDB, 유료 서비스 가격 비교는 이 책 범위 밖이다. 공식 성능 최적화 URL 두 차례 접근에 실패해 그것을 읽었다고 쓰지 않는다. N+1 부분은 명시적 호출 계획을 직접 세는 예제이고 제품 성능 주장에 사용하지 않는다.

실제 로컬 코드 검증

2026-10-21 root가 Linux / Node 24.19.0에서 Prisma CLI·Client·SQLite adapter 7.10.1을 설치했다. migrate dev로 init SQL을 생성·적용하고 generate, tsc --noEmit, demo를 실행했다. demo의 순차 요청 두 번 결과는 Run 한 건이었다. 임시 DB마다 migrate deploy를 적용하는 통합 테스트 10개가 통과했다. 코드와 lockfile은 ../examples/에 있다.

최초 tsx CLI 실행은 /tmp IPC 파이프 생성 권한으로 실패했다. npm 스크립트를 node --import tsx로 바꾸어 demo·테스트를 다시 실행한 뒤 통과했다. 권한을 늘리거나 시스템 설정을 바꾸지 않았다. Windows/macOS 설치, PostgreSQL 동시성, 실제 인증 서비스는 실행하지 않았다.

recordRun은 순차 동일 요청의 재실행을 다루며 동시 요청의 모든 실패를 성공으로 흡수하지 않는다. 서로 다른 요청의 결과가 역순으로 도착하는 상태 전이 문제도 별도 정책이 필요하다. scoped-update는 신뢰한 서버 프로젝트 ID를 전제로 한 변경 범위 예제다.
