모형의 경계

  • 가중치 byte = P×bit/8. 부가정보를 제외한 이상값이며 실제 양자화 파일을 측정하지 않는다.
  • KV = 2×L×H_KV×d×T×B×byte. full Attention·독립 동일 길이 시퀀스·공유와 압축 없음.
  • 4×4 행렬 타일은 정확한 행렬곱을 계산한다. 적재 횟수 2n³/tile은 입력만 세며 캐시·출력 쓰기·정렬을 생략한다.
  • 첫 출력은 prefill 끝에서 선택한다. G개 출력에는 G−1번 decode를 가정한다. 위치 수 비교는 전체 Attention FLOP가 아니다.
  • Roofline은 8B Dense의 선형 연산량 약 2×P×B FLOP와 한 단계당 4 GB 가중치 읽기를 사용한다. KV와 중간값 등을 제외한 이상적 하한이다.
  • MoE는 공통 2B+expert당 0.5B인 가상 모형이다. 실제 Qwen과 섞지 않는다.
  • 전송 시간은 GB/(GB/s)의 순수 시간이다. CPU 연산·시작 지연·프로토콜·중첩을 생략한다.
  • 종합 예산의 가중치 부가정보 비율과 실행 여유는 독자가 정한 가정이다. 실제 로드 순간 최대 메모리·성능·품질은 측정하지 않는다.

공식 사례의 확인 기록

2026-10-08 모델 발행자의 카드와 config.json을 열어 확인했다. Qwen3-8B: 전체 약 8.2B, 36층, KV 8 heads, head_dim 128. Qwen3-30B-A3B: 전체 약 30.5B, 활성 약 3.3B, 48층, KV 4 heads, head_dim 128. 공식 카드 파라미터는 반올림 사양이며 원소 수를 파일에서 직접 센 값은 아니다. 출처 링크와 각 주장에 쓰는 문서는 본문 참고 자료에서 볼 수 있다.

수정·문제 해결

최종 과제의 독립 검증값을 처음 적을 때 GiB 소수 자릿수 오기가 있었다. 정확한 byte 합계 36,927,352,832 및 23,727,352,832로 비교하도록 고쳤다. 화면의 34.39와 22.10 GiB 표시는 변하지 않았다.

이 실행 환경의 기본 Playwright 브라우저 경로에는 실행 파일이 없었고 다운로드도 정상 ZIP을 반환하지 않았다. 기존 사용 가능한 Chromium 153을 PW_EXECUTABLE_PATH로 지정했다. 재현 테스트는 이 환경 경로를 코드에 고정하지 않고 환경변수로 받는다.

모바일 SVG 축소 화면에서 숫자가 작고 수평 스크롤이 필요했다. 좁은 화면에서는 같은 값을 큰 레이블·수치·막대로 다시 표시하도록 수정했다. 비교 입력과 계산 모형은 그대로 유지했다.

문서 허브 · 서가

장 그림과 다른 책 연결 (2026-10-08 보강)

책 기준(서가 기본지침 10절, docs/08 9절)에 맞추어 12개 장의 "먼저 개념 잡기"에 움직이는 개념 그림을 넣었다. 그림은 js/figures.js가 장 ID별로 그리며, 용량·KV·roofline·MoE·모델 사양·예산처럼 숫자가 있는 그림은 js/math.js의 같은 함수로 계산한다. 파일 흐름·데이터 경로·저장 계층·타일은 단순화한 개념도라고 캡션에 밝힌다. 기존 흐름 상자는 그림 아래 글 대체로 남겼고, 움직임은 prefers-reduced-motion에서 멈춘다(교대로 켜지는 그림은 첫 장면만 보인다). 760px 이하에서는 그림이 최소 520px 폭을 유지하고 그림 안에서 옆으로 밀어 본다.

다른 책 연결은 12개 장 모두에 cross로 두었다(22개, 컴퓨터 원리·AI Book·벡터와 행렬·확률과 통계·검색과 RAG·추론 최적화). 각 항목은 도착 장, 이동 이유, 돌아올 곳을 문장에 담는다. 반대 방향으로 AI Book(attention·generation·inference), 컴퓨터 원리(bits), 벡터와 행렬(matrix·layer), 확률과 통계(interval)에서 이 책으로 오는 링크 7개를 추가했다. 서가에는 공통 개념 "어텐션과 KV 캐시"와 읽기 노선 "답은 왜 한 글자씩 나올까"를 더하고 기존 개념 6개에 이 책의 장을 이었다. 반대 방향 링크와 공통 개념은 같은 날 병합된 큐레이션 작업(PR #21)과 겹치지 않게 정리했다.
