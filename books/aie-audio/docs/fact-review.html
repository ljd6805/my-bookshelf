위치문제근거수정
#whisper 첫 문단·흐름 (js/content.js)Whisper 입력이 “언제나 로그 멜 80채널”이라고 했으나, 같은 장이 기준으로 삼는 Large-v3와 Turbo는 128채널Hugging Face openai/whisper-large-v3 모델 카드: “128 Mel frequency bins instead of 80”(원본 레슨의 오류)“멜 채널은 80개(Large-v3와 Turbo는 128개)”로 고치고 흐름 카드도 맞춤. 어휘 수에 Large-v3의 51,866개를 덧붙임
#mel 과제별 특징 표음성 인식 특징을 로그 멜 80개로만 적음위와 같음“Whisper Large-v3·Turbo는 128개”를 덧붙임
#whisper Whisper 내부와 변형Whisper가 “자기 학습 통계로” 로그 멜을 정규화한다고 함openai/whisper audio.py: log10 → 최댓값 − 8로 바닥 자르기 → (x + 4) ÷ 4. 데이터셋 평균·표준편차를 쓰지 않음(원본 레슨의 오류)실제 계산 방식으로 바꿈

#classify 데이터와 지표 표AudioSet을 632개 클래스로만 적음AudioSet 공식 페이지: 온톨로지 632개, 라벨이 붙은 데이터는 527개 클래스“온톨로지 632개 클래스(라벨이 붙은 것은 527개)”
#codec 식 설명원본의 Mimi 4.4 kbps만 소개해, 코드북 8개 설정의 실제 비트레이트가 빠짐Moshi 논문(arXiv 2410.00037): 코드북 크기 2,048, 코드북 8개, 12.5 Hz에서 1.1 kbps. 4.4 kbps는 32개 코드북 값과 일치두 값을 구분해 설명
#pipeline 실시간 처리의 부품링 버퍼의 용량이 “곧 지연의 바닥”이라고 함원본 레슨 11: 링 버퍼 크기 ≈ 최대 지연 × sr, 지연의 바닥은 처리 전에 쌓아 두는 버퍼(“Buffering 500 ms … is your latency floor”)용량과 쌓아 두는 양을 구분해 고침

#safety 워터마크 비교 표AudioSeal 검출기가 “실시간의 485배”라고 함AudioSeal 논문 5.5절: 생성은 WavMark보다 14배, 검출은 평균 두 자릿수, 워터마크 없는 소리에서 485배 빠름. 실시간 대비 수치가 아님“검출이 WavMark보다 평균 두 자릿수 빠름(워터마크 없는 소리에서 485배)”

보류 (고치지 않고 남긴 것)

  • #tts: FastSpeech 2가 Tacotron 2보다 “약 10배 빠름”은 원본 레슨의 표현입니다. 논문마다 비교 대상과 측정(학습·추론, 멜 생성·전체)이 달라 한 숫자로 바로잡기 어렵습니다.
  • #pipeline과 #final: 끼어들기 반응 목표가 100 ms(원본 레슨 11)와 150 ms(원본 레슨 17)로 다릅니다. 둘 다 원본에 있는 값입니다. 사전 버퍼 200~400 ms(레슨 12)와 300~500 ms(레슨 14), SECS 0.70(레슨 08)과 0.75(레슨 17)도 같은 경우입니다.
  • #tts·#safety: EU AI Act와 캘리포니아 법이 워터마크와 동의 기록을 “요구한다”는 요약은 원본의 정리이며, 실제 조문(예: AI Act 제50조의 합성 콘텐츠 표시 의무)은 동의 기록까지 직접 요구하지 않을 수 있습니다. 책이 이미 “원본 커리큘럼 기준, 해당 지역의 공식 문서로 확인”을 붙였으므로 그대로 두었습니다.
  • #whisper: MMAU-Pro의 Gemini 2.5 Pro 약 60%는 원본 기준입니다. MMAU-Pro 논문 초록은 Gemini 2.5 Flash 59.2%를 대표값으로 듭니다. 확인일을 붙인 원본 수치라 두었습니다.
  • #wave: 16 kHz에서 1024점 FFT의 “빈 512개”는 원본의 “usable bins” 표현입니다. rfft 출력은 0 Hz와 8 kHz를 포함해 513개입니다. 16비트 PCM을 “±32,767”로 적은 것도 원본 표현이며 정확한 int16 범위는 −32,768~32,767입니다. → 등록 단계에서 시리즈 진행 세션이 본문을 “빈 513개(양 끝 포함)”와 “−32,768~32,767”로 고쳤습니다.

확인하지 못한 것

이 환경의 프록시가 curl의 외부 요청을 막아 외부 URL 28개의 HTTP 응답 코드는 직접 확인하지 못했습니다. 대신 모두 원본 레슨의 참고 문헌 주소와 같음을 확인했고, Whisper 모델 카드·audio.py·Kyutai 코덱 설명·Moshi·AudioSeal·VoxCeleb2 논문·AudioSet 페이지는 웹으로 열어 내용을 확인했습니다. 벤치마크 표의 WER·EER·MOS·FAD 같은 모델 성능 수치(Parakeet 1.40%, ECAPA 0.87%, ASVspoof 5 EER 7.23% 등)는 원본 레슨과 일치하는지만 확인했고 각 논문·순위표에서 하나씩 재확인하지는 않았습니다. 책은 이 수치에 “원본 커리큘럼 기준(확인일 2026-10-08)”을 붙여 두었습니다. 실제 음성으로 실험 결과를 재는 검증은 하지 않았습니다.
