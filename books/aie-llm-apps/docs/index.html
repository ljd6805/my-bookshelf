LLM 엔지니어링 · 제작 문서

「AI 엔지니어링 처음부터」 시리즈 12권 《LLM 엔지니어링 · 프롬프트에서 서비스까지》의 기획, 원본 레슨 대응, 구현, 검증을 한곳에 모았습니다. 작성일은 2026-10-08입니다. 원본은 rohitg00/ai-engineering-from-scratch(MIT)의 Phase 11 · LLM Engineering입니다. 원문과 코드를 옮기지 않고 개념과 순서만 참고해 새로 썼습니다.

1. 기획

  • 독자: LLM API를 한두 번 불러 본 개발자입니다. 데모는 만들 수 있지만, 출시 뒤 답이 흔들리거나 청구서가 불어날 때 어디를 고쳐야 할지 설명하기는 어려워합니다.
  • 끝의 행동: 예산을 넘은 LLM 서비스의 청구서와 민원을 받으면 캐시 임계값과 모델 분배 같은 손잡이를 고릅니다. 그 선택이 정확도와 안전을 해치지 않는다는 증거(평가 구간, 잘못된 적중 수, 막은 비율)를 무엇으로 모을지도 말할 수 있습니다.
  • 공통 사례: 가상의 온라인 서점 "책다락"의 고객 지원 도우미 "다락 도우미"입니다. 반품 기한 질문 하나에서 출발해 장마다 부품을 하나씩 붙입니다. 지시문, 예시, JSON, 컨텍스트 예산, 정책 문서 검색, 말투 어댑터, 주문 조회 도구, 평가 세트, 입출력 검사, 캐시, 환불 승인 그래프 순서입니다. 모든 장의 첫 문단은 앞 장에서 붙인 부품으로 시작합니다.
  • 이야기 방식: 제품을 완성한다. 마지막 장은 출시 2주 차의 새 상황입니다. 캐시 임계값을 올린 뒤 예산을 넘은 청구서를 받고, 앞 장들의 도구로 대응합니다.
  • 범위: 원본 Phase 11의 레슨 17개를 모두 다룹니다. 임베딩·RAG·고급 RAG(레슨 04·06·07)는 서재의 "검색과 RAG" 책과 AI Book #rag가 깊게 다루므로 5장에서 한 문단으로 요약하고 링크로 보냅니다. 대신 원본에만 있는 저장 용량과 검색 비용 계산에 분량을 씁니다. KV 캐시의 GPU 쪽 원리는 LLM 시스템 책 #cache에, 에이전트 반복의 개념은 AI Book #agents에 맡깁니다.
  • 증거: 17개 실험 가운데 13개는 원본 레슨의 식이나 규칙을 브라우저에서 실제로 계산합니다. 소프트맥스와 top-p, 퓨샷 토큰, 이항 다수결, 컨텍스트 예산, 벡터 용량, LoRA 파라미터와 메모리, 도구 지연, Wilson 구간, 카파, 탐지 임계값과 기저율, 프롬프트 캐시 배수, 한 달 비용, 여러 층 방어의 통과율이 여기에 속합니다. 로짓·유사도·탐지 점수와 층별 차단율은 교육용 가정값입니다. 제약 디코딩 마스크, MCP 요청 판정, 의미 캐시 판정, 상태 그래프 실행은 규칙을 그대로 따르는 미리 정한 시나리오입니다. 각 실험의 결과 문장에 어느 쪽인지 적었습니다. 시점에 따라 바뀌는 사실(단가 배수, MCP 개정판, 모델 가격)은 "원본 커리큘럼 기준(확인일 2026-10-08)"으로 표시했습니다.

부 구성은 네 묶음입니다. 지시와 형식(1~3장), 맥락과 적응(4~6장), 도구와 검증(7~9장), 서비스 운영(10~12장).

4. 검증

검증일은 2026-10-08입니다. 실제 LLM API, MCP 서버, LangGraph를 실행하거나 GPU 메모리를 잰 검증은 아닙니다.

  • 계산 검사: npm test --prefix books/aie-llm-apps가 통과했습니다. 계산 함수마다 대표값, 경계값, 불변 조건을 확인합니다. 예시는 다음과 같습니다.

    • 제약 디코딩의 모든 단계에서 목표 토큰이 허용 집합에 들어감
    • 컨텍스트 압축은 사용량을 늘리지 않음
    • Llama 2 7B 파라미터 6,738,415,616개
    • 도구 병렬 지연 ≤ 순차 지연
    • MCP 오류 코드 −32602·−32022·−32020
    • Wilson 구간 폭이 n에 따라 줄어듦
    • 카파 0과 1의 경계
