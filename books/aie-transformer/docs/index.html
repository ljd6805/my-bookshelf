트랜스포머 깊이 보기 · 제작 문서

「AI 엔지니어링 처음부터」 시리즈 08권 《트랜스포머 깊이 보기 · 셀프 어텐션에서 스케일링 법칙까지》의 기획, 원본 레슨 대응, 구현, 검증을 한곳에 모았습니다. 작성일 2026-10-08. 원본은 rohitg00/ai-engineering-from-scratch(MIT)의 Phase 7 · Transformers Deep Dive이며, 원문과 코드를 옮기지 않고 개념과 순서만 참고해 새로 썼습니다.

1. 기획

  • 독자: 신경망과 역전파는 알고, 어텐션 그림도 한 번쯤 봤지만 Q·K·V를 직접 계산하거나 모델 설계표의 숫자가 왜 그렇게 정해졌는지 설명해 본 적은 없는 사람.
  • 끝의 행동: “문맥을 네 배로 늘려 달라”, “응답을 두 배 빠르게”, “같은 예산에서 품질을 올려 달라” 같은 요구를 받으면, 설계표에서 바꿀 칸 하나를 고르고 메모리·속도·손실을 다시 계산해 통과 여부와 아직 부족한 증거를 말할 수 있습니다.
  • 공통 사례: 작은 언어 모델 ‘도란’의 설계표와 문장 “나는 어제 산 책을 오늘 다 읽었다”. 장마다 설계표의 칸 하나(√d 나누기, 헤드 수, 위치 방식, 정규화, 목적 함수, 전문가 수, 캐시 방식, 데이터 양, 디코딩 방식)를 채우고, 같은 문장의 ‘읽었다’가 어디를 보는지로 결과를 확인합니다.
  • 이야기 방식: 하나의 제품을 완성한다. 1장에서 빈 설계표로 시작해 11장까지 칸을 채우고, 마지막 장은 새 요구 세 가지에 그 설계표를 다시 짜게 합니다.
  • 범위: 원본 Phase 7의 레슨 16개 전부. 어텐션 가중치의 직관은 AI Book(#attention)에, 행렬곱 실행·KV 캐시의 기본 크기·프리필과 디코드·병목·실행 예산은 LLM 시스템 책에 맡기고 한 문단 요약과 링크로 보냅니다. 이 책은 원본에만 있는 구현 관점(√d 나누기의 통계, 헤드 분할 규칙, RoPE의 상대 거리 성질, 사전 정규화와 RMSNorm, 80·10·10 규칙, 삼각 마스크 유도, 패치·프레임 토큰 수, 라우터 균형, 타일 softmax, 어텐션 변형별 캐시, 친칠라 배분, 추측 디코딩의 기대 토큰)에 분량을 씁니다.
  • 증거: 실험 16개 중 15개는 원본 레슨의 식을 브라우저에서 실제로 계산합니다(시드 고정 난수로 만든 점수와 softmax, 회전 행렬, 파라미터 수, 정규화, 마스킹 표본, 타일 softmax의 오차, KV 캐시 바이트, Chinchilla 손실식 격자 탐색, 기대 토큰 공식). 라우터 실험은 실제 계산이지만 토큰 선호도는 합성 분포입니다. 마지막 장의 설계 재계산은 실제 공식을 쓰되 요구 기준값과 MoE 품질 판정 불가는 미리 정한 시나리오입니다. 각 실험 결과 문장과 “무엇을 계산하나요?”에 어느 쪽인지 적었습니다. 학습된 모델의 실제 가중치는 쓰지 않습니다.

부 구성: 어텐션 부품(1~4장) · 블록과 가족(5~7장) · 키우고 빠르게(8~11장) · 마지막 과제(12장).

검증일 2026-10-08. 실제 모델을 학습하거나 GPU에서 속도를 잰 검증은 아닙니다.

5. 2026-10-12 보충

  • 공통: 12장 모두에 전이 문항(transfer, “다른 상황에 써 보기”)을 더했습니다. 본문과 다른 소재·숫자에 그 장의 도구를 써야 풀리며, 계산 문항은 node로 따로 검산했습니다. 확인 문제와 전이 문항의 보기는 화면에서 돌려 정답 자리가 장 번호에 따라 1·2·3번에 고르게 오고(quizOrder, 확인 문제 index % 3, 전이 (index + 1) % 3), data-answer·data-transfer는 원래 번호를 유지합니다. 장 머리는 “확인 문제 2개”로 보입니다. 자산 버전은 20261012-supp1입니다.
  • #bertgpt: formula의 x_<t가 태그로 읽혀 손실 식과 마스크 정의가 화면에서 사라지던 오류를 x_&lt;t로 고쳤고, 브라우저에서 식 전체가 보이는 것을 확인했습니다.
