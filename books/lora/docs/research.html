0. 이 노트를 읽는 법 (은재)

확인일은 모두 2026-10-19입니다. 이 노트는 글작성팀과 시각·실험팀이 본문과 실험에 그대로 옮겨 써도 되는 사실과, 옮길 때 붙여야 할 조건을 모은 것입니다. 검수팀 유진은 여기서 검수를 시작합니다.

논문은 모두 원문을 직접 읽고 대조했습니다. 이 작업 환경에서는 arxiv.org가 막혀 있어서, 지호가 Hugging Face Papers가 보관한 같은 논문의 본문(arXiv HTML이나 PDF를 옮긴 마크다운, hf://papers/<arXiv ID>/paper.md)을 읽었습니다. 아래 출처 표의 링크는 독자가 열 원문 주소인 arXiv 초록 페이지로 적었습니다. 모델 설정 값은 Hugging Face 저장소의 config.json을 직접 열어 확인했습니다. 쪽 번호는 마크다운 본문에 남지 않아서, 위치는 절·표·그림 번호로 적었습니다.

상태는 셋으로 나눕니다. 확인함은 원문 문장이나 표에서 같은 값을 찾았다는 뜻입니다. 다르게 확인함은 원문에 근거는 있지만 의뢰된 문장과 값·위치·표현이 달라 고쳐 써야 한다는 뜻이고, 맞는 값을 함께 적었습니다. 확인 못함은 원문에서 찾지 못한 것입니다. 확인 못한 것은 본문에 쓰지 않습니다.

시점에 따라 바뀌는 정보는 거의 없습니다. 논문 수치는 출판본 기준으로 고정되어 있습니다. 다만 Hugging Face 저장소의 설정 파일과 arXiv 판 번호는 바뀔 수 있어 표에 “변화 가능”으로 표시했습니다. 비교에 쓴 교재나 강의는 없고, 본문과 실험은 이 노트를 바탕으로 새로 씁니다.

2. 사실 주장 표 (은재 정리, 지호 위치 확인)

“주장” 칸은 본문에 그대로 옮겨도 되는 한국어 문장입니다. 조건이 붙은 것은 조건까지 함께 옮겨 주세요.

ID주장원문 인용위치상태
L1-aLoRA는 사전학습 가중치 W₀ ∈ ℝ^{d×k}를 고정하고, 갱신을 ΔW = BA로 나타낸다. B ∈ ℝ^{d×r}, A ∈ ℝ^{r×k}이며 r은 min(d, k)보다 훨씬 작다. 학습하는 것은 A와 B뿐이다.“W0+ΔW=W0+BA, where B∈ℝ^{d×r}, A∈ℝ^{r×k}, and the rank r≪min(d,k). During training, W0 is frozen”S1 4.1절, 식 (3)확인함
L1-bA는 무작위 가우스 분포로, B는 0으로 초기화한다. 그래서 학습을 시작할 때 ΔW = BA는 0이다.“We use a random Gaussian initialization for A and zero for B, so ΔW=BA is zero at the beginning of training.”S1 4.1절확인함
L1-cΔWx에는 α/r을 곱한다. Adam을 쓸 때 α를 조정하는 일은 초기화를 알맞게 맞추면 학습률을 조정하는 일과 거의 같아서, 저자들은 처음 시도한 r 값을 α로 정하고 α를 따로 조정하지 않았다. 이 배율 덕분에 r을 바꿀 때 하이퍼파라미터를 다시 맞출 필요가 줄어든다.“We then scale ΔWx by α/r … tuning α is roughly the same as tuning the learning rate if we scale the initialization appropriately. As a result, we simply set α to the first r we try and do not tune it.”S1 4.1절확인함
L2-aGPT-3 175B를 Adam으로 전체 미세조정할 때와 비교해, LoRA는 학습하는 매개변수 수를 1만 분의 1로, GPU 메모리 요구량을 3분의 1로 줄일 수 있다.“LoRA can reduce the number of trainable parameters by 10,000 times and the GPU memory requirement by 3 times.”S1 초록확인함
L2-bGPT-3 175B에서 학습 중 VRAM 사용량은 1.2TB에서 350GB로 줄었다. r = 4로 query·value 투영 행렬만 적응시키면 체크포인트는 약 350GB에서 35MB로, 대략 1만 분의 1이 된다. 배포할 때는 350GB 기본 모델이 여전히 필요하다.“we reduce the VRAM consumption during training from 1.2TB to 350GB. With r=4 and only the query and value projection matrices being adapted, the checkpoint size is reduced by roughly 10,000× (from 350GB to 35MB)”S1 4.2절 “Practical Benefits and Limitations”, 각주 4확인함
L2-cGPT-3 175B에서 LoRA 학습은 전체 미세조정보다 25% 빨랐다. V100 한 장당 처리량이 32.5 토큰/초에서 43.1 토큰/초로 늘었다(모델 병렬 조각 수는 같게 둠).“We also observe a 25% speedup during training on GPT-3 175B compared to full fine-tuning” / 각주 5 “32.5 tokens/s per V100 GPU … 43.1 tokens/s per V100 GPU for LoRA”S1 4.2절, 각주 5확인함 (43.1/32.5 = 1.326이라 처리량 기준으로는 약 33% 증가. 본문에는 논문 표현 “25% 빨라짐”과 각주의 두 값을 함께 쓰고, 두 비율을 섞어 계산하지 않는다)
L2-d저장 예: 적응 모델 100개를 저장하면 350GB + 35MB × 100 ≈ 354GB로, 전체 미세조정 사본 100개의 약 35TB와 대비된다.“storing 100 adapted models only requires 350GB + 35MB * 100 ≈ 354GB as opposed to 100 * 350GB ≈ 35TB”S1 각주 4확인함
L3배포할 때 W = W₀ + BA를 미리 계산해 저장하면 추론은 평소처럼 하므로, 전체 미세조정 모델에 비해 추가 지연이 구조상 생기지 않는다. 다른 작업으로 바꿀 때는 BA를 빼서 W₀를 되찾고 다른 B′A′를 더한다.“we can explicitly compute and store W=W0+BA and perform inference as usual … we can recover W0 by subtracting BA and then adding a different B′A′”S1 4.1절 “No Additional Inference Latency”확인함. 같은 절의 한계도 함께 쓴다: 가중치를 병합하면 A·B가 다른 작업의 입력을 한 번의 순전파로 묶기 어렵다(S1 4.2절 끝).
L4-aGPT-3 175B에서 학습 매개변수 예산을 18M(FP16으로 약 35MB)으로 고정하고 96층 전체에 적용해 비교하면, Wq와 Wv를 함께 r = 4로 적응시킨 경우가 전반적으로 가장 좋았다.“We set a parameter budget of 18M (roughly 35MB if stored in FP16) on GPT-3 175B, which corresponds to r=8 if we adapt one type of attention weights or r=4 if we adapt two types, for all 96 layers.” / “Adapting both Wq and Wv gives the best performance overall.”S1 7.1절, 표 5다르게 확인함: 18M 예산 비교는 표 6이 아니라 표 5이다.
L4-b순위 r을 바꾼 비교(표 6)에서 {Wq, Wv}를 함께 적응시키면 r = 1만으로도 WikiSQL과 MultiNLI에서 경쟁력 있는 성능이 나왔다. Wq 하나만 적응시키면 더 큰 r이 필요했다. 저자들은 모든 작업에서 작은 r이 통한다고 기대하지는 않는다고 덧붙였다.“To our surprise, a rank as small as one suffices for adapting both Wq and Wv on these datasets while training Wq alone needs a larger r.” / 각주 6 “we do not expect a small r to work for every task or dataset”S1 7.2절, 표 6, 각주 6다르게 확인함: 원문 표현은 “r = 1 또는 2”가 아니라 “r = 1로도 충분”이며, 이 표는 18M 예산 고정 실험이 아니다(r은 1, 2, 4, 8, 64). 표 6 값: Wq·Wv의 WikiSQL 73.4(r=1)~73.8(r=8), MultiNLI 91.3~91.6.
L4-cr = 8과 r = 64로 학습한 A의 특잇값 방향을 비교하면 가장 위 방향들은 크게 겹치고 나머지는 겹치지 않는다. 저자들은 위쪽 방향이 가장 쓸모 있고 나머지는 학습 중 쌓인 무작위 잡음일 가능성이 크다고 해석했다.“Directions corresponding to the top singular vector overlap significantly between A_{r=8} and A_{r=64}, while others do not.” / “other directions potentially contain mostly random noises”S1 7.2절, 그림 3 (96층 중 48번째 층)확인함
L4-dΔW는 W의 가장 큰 특잇값 방향을 되풀이하지 않고, W에서 강조되지 않은 방향을 키운다. GPT-3 48번째 층 Wq, r = 4에서 그 증폭 배율은 약 21.5 ≈ 6.91/0.32이다.“ΔW only amplifies directions that are not emphasized in W. Third, the amplification factor is rather huge: 21.5≈6.91/0.32 for r=4.”S1 7.3절, 표 7확인함 (r = 64에서는 배율이 더 작다고 원문이 밝힘)
L5원 논문의 실험은 셀프 어텐션 가중치에만 LoRA를 적용하고 MLP 모듈은 고정했다. 대부분의 실험에서는 Wq와 Wv에만 적용했다. MLP·LayerNorm·편향의 적응은 후속 연구로 남겼다.“We limit our study to only adapting the attention weights for downstream tasks and freeze the MLP modules” / “we only apply LoRA to Wq and Wv in most experiments for simplicity”S1 4.2절, 5.1절확인함
L-extraGPT-3 175B에서 학습 매개변수 |Θ|는 |Φ₀|의 0.01%까지 작아질 수 있다. GPT-3의 전체 순위 d는 12,288이다.“the number of trainable parameters |Θ| can be as small as 0.01% of |Φ0|” / “even when the full rank (i.e., d) is as high as 12,288”S1 2절 끝, 1절확인함
I1-a무작위 투영으로 전체 공간에 되돌린 학습 매개변수 약 200개만 최적화해도 RoBERTa 모델로 MRPC에서 전체 매개변수 미세조정 성능의 90%에 이른다. 모델은 RoBERTa-Large이고, 표 1의 SAID 추정값은 207이다(DID는 322).“by optimizing only 200 trainable parameters randomly projected back into the full space, we can tune a RoBERTa model to achieve 90% of the full parameter performance levels on MRPC” / “With RoBERTa-Large, we can reach 90% of the full fine-tuning solution of MRPC using roughly 200 parameters”S2 초록, 4.2절, 표 1확인함 (200은 어림값. 같은 표에서 QQP는 774)
I1-bd₉₀은 부분공간에서 학습한 성능이 전체 학습 지표의 90%에 이르는 가장 작은 차원 d이다. 예를 들어 전체 학습 정확도가 85%면 0.9 × 85% = 76.5%에 이르는 가장 작은 d이다.“Li et al. (2018) defined the satisfactory solution as being 90% of the full training metric … reach 0.9 ∗ 85% = 76.5% accuracy; we call this dimension d90.”S2 3절확인함
I1-c사전학습을 더 할수록 내재 차원이 줄었고(RoBERTa-Base를 처음부터 다시 학습하며 측정), 정해진 사전학습 갱신 횟수 뒤에는 큰 모델일수록 내재 차원이 낮은 경향이 있었다.“pre-training implicitly minimizes intrinsic dimension and, perhaps surprisingly, larger models tend to have lower intrinsic dimension after a fixed number of pre-training updates”S2 초록, 5.1절(그림 2), 5.2절(그림 3)확인함 (“경향”과 “정해진 갱신 횟수 뒤”라는 조건을 지운 채 “크면 언제나 낮다”로 쓰지 않는다)

R1-brsLoRA는 배율을 γ_r = α/√r로 둔다. 저자는 r → ∞ 극한 분석으로, 순위에 안정한 어댑터가 되려면 γ_r이 1/√r 차수여야 한다(Θ(1/√r))는 정리를 증명했다. 이렇게 바꾸면 큰 순위에서 성능이 좋아졌다(Llama 2, OpenOrca 2만 예제, r = 4~2048).“γ_r = α/√r … We call our method … the rank-stabilized LoRA (or rsLoRA) method.” / “all adapters are rank-stabilized if and only if γ_r ∈ Θ_r(1/√r)”S8 3절 식 (4), 정리 3.2, 4절 그림 2확인함 (“r이 무한히 커지는 극한”의 결과이며, 원문도 실제 성능 차이는 실험으로 확인해야 한다고 적음)

3. 확인하지 못한 것과 쓰지 않을 것 (은재)

  • meta-llama 공식 설정 파일: meta-llama/Llama-2-7b-hf, -13b-hf는 접근 승인이 필요한 저장소라 열지 못했습니다. 값은 NousResearch 사본(S16·S17)으로 확인했고, 13b 사본은 파일 안에 원본 이름을 적고 있습니다. 본문 출처에는 “공식 저장소의 사본 기준”이라고 밝히고, 검수 때 공식 파일 접근이 되면 다시 대조합니다.
  • Llama 2의 정확한 매개변수 수: 논문은 “7B”, “13B”로만 적습니다. 아래 §calc의 6,738,415,616과 13,015,864,320은 설정 파일로 계산한 값이며 논문이나 모델 카드의 문장으로 확인한 값이 아닙니다. 본문에는 “설정으로 계산한 값”이라고 씁니다. Mistral-7B의 7,241,732,096도 같습니다.
  • 학회 서지: S2(ACL 2021로 알려짐), S3(ICLR 2018), S5(ACL 2021), S6(EMNLP 2021), S7(NeurIPS 2023), S10(TMLR), S11(SC20), S13(MLSys 2024)의 학회명은 이번에 원문에서 확인하지 못했습니다. S13 본문은 “MLSys 심사 중” 양식입니다. 그래서 출처 표에는 arXiv 연도만 적었습니다. 학회명이 필요하면 검수 때 출판사 페이지로 확인합니다.
  • “r이 1 또는 2면 충분”: 원문 표현은 “r = 1로도 충분”(표 6 설명)과 “r은 1이나 2일 수 있다”(1절 “a very low rank (i.e., r …) can be one or two”)가 함께 있습니다. 둘 다 GPT-3 175B, WikiSQL·MultiNLI 조건의 결과이며, 저자 스스로 모든 과제에 통한다고 보지 않았습니다(각주 6). 조건 없이 “LoRA는 r = 1이면 된다”로 쓰지 않습니다.
  • “LoRA가 더 강한 정규화”(B1-d): v2 초록에서는 찾지 못했습니다. 망각 비교로 한정한 문장만 씁니다.
  • DoRA 표 번호: 상식 추론 향상 폭은 1절 문장으로만 확인했고, 해당 표의 번호와 과제별 값은 이번에 읽지 않았습니다.
  • QLoRA의 65B 메모리 “41GB”: 표 1의 Guanaco 65B 크기 41GB는 배포 모델 크기이며 학습 메모리가 아닙니다. 본문에서 학습 메모리와 섞지 않습니다.
  • S-LoRA의 “수천 개”: 정확한 최대 어댑터 수(예: 2,000개)는 실험 절을 읽지 않아 확인하지 못했습니다. “수천 개”로만 씁니다.

4. 수아의 검산 (책 코드와 따로 계산)

모든 값은 Python 정수 계산으로 따로 냈습니다(2026-10-19). 단위를 먼저 정합니다. 매개변수 수는 개, 메모리는 10진 GB(10⁹ 바이트)와 MB(10⁶ 바이트)로 적습니다. 논문들이 10진 단위로 적기 때문입니다. 2진 단위가 필요하면 GiB(2³⁰)를 따로 괄호에 둡니다. 둘은 약 7% 차이가 납니다.

모델 매개변수 식(가정: 편향 없음, 입력 임베딩과 출력 lm_head를 따로 둠, 층마다 RMSNorm 두 개와 마지막 RMSNorm 하나, SwiGLU라 MLP 행렬 셋):

전체 = 2·V·h + L·(2·h² + 2·h·kv + 3·h·i + 2·h) + h, 여기서 kv = KV 헤드 수 × 헤드 차원(= h·KV헤드/헤드)입니다. 어텐션 항은 Wq·Wo가 h×h, Wk·Wv가 h×kv입니다.

경계값 r = 0이면 LoRA 매개변수는 0개이고 모델은 W₀ 그대로입니다. B = 0으로 시작하는 LoRA(L1-b)의 첫 걸음과 같은 출력입니다. r = min(d, k)이면 ΔW가 아무 행렬이나 될 수 있어 표현력은 전체 미세조정과 같아지지만, q·v 하나당 매개변수는 r·(d+k) = 4096·8192로 원래 행렬(4096²)의 두 배가 됩니다. 실험 슬라이더는 이 두 끝을 모두 넣어 보여 주면 좋겠습니다.

구분 위 표는 모두 실제 계산입니다. GPU 메모리를 “몇 GB 든다”로 그리는 실험은 모델 상태만 센 시나리오임을 화면에 밝혀야 합니다. 활성값은 배치·문장 길이에 따라 달라 이 노트에서는 기준값을 내지 않았습니다.
