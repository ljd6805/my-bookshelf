독자와 끝의 행동

시스템 이해편을 읽고 파라미터·KV·대역폭을 구분할 수 있는 개발자를 대상으로 한다. 마지막에는 회의록 요약 서비스의 가상 측정 기록에서 성능·메모리·정확성 조건을 함께 만족하는 변경을 고르고, 실제 GPU에서 재현할 측정 계획을 쓴다.

공통 사례와 범위

“회의 내용을 요약해 줘”라는 같은 요청을 사용한다. 첫 토큰과 토큰 간격을 구분하고, 비동기 측정·타임라인·커널의 주소 접근·메모리 재사용·서빙 스케줄을 차례로 조사한다. 브라우저는 실제 GPU를 측정하지 않는다. 공식 오픈웨이트 모델은 재현 기록의 대상으로 다루며, 교육용 숫자를 해당 모델의 벤치마크처럼 표시하지 않는다.

구성

  1. 측정: 지표, 비동기 시간, 타임라인.
  2. 커널: 스레드 인덱스, 연속 접근, 타일과 자원 제한.
  3. 메모리: 처리량 근거, 연산 융합·어텐션, KV 페이지.
  4. 서비스: 배치, GPU 사이 통신, 최종 개선안 검증.

12장, 13개 실험, 장마다 확인 문제 하나. 1장 완결 → 같은 사례로 3장 완결 → 전체 확장 순서로 구현한다. 장 화면의 일곱 블록과 표지의 다섯 구역을 유지한다.

변경 파일과 독자에게 생길 변화

books/llm-performance/에 독립 본문·계산·화면·실험·실행 예제·테스트·HTML 문서를 만든다. AI Book의 구조를 출발점으로 삼고 공통 글꼴을 쓴다. catalog.json·생성된 루트 index.html·CI·work-state.json을 갱신한다. 시스템 이해편에서 새 책으로 가는 이유 있는 링크를 추가한다. 서가 색은 이웃과 구분되는 rose, 분류는 인공지능, 책등은 “추론 최적화”로 한다.

검증 계획

L1: 경로·표준 구조·라벨·320/390/1280px 배치. L2: 모든 실험의 예제·직접 입력·초기화·키보드·확인 문제, 서가 삽화 동작과 동작 줄이기. L3: 대표값·경계값·독립 산술 및 수치 불변 조건. L4: 실제 독자의 전이 과제 수행은 미검증으로 남긴다. PyTorch/CUDA 실행 예제는 이용 가능한 환경에서만 검증하고, CUDA 실행 여부를 별도로 밝힌다.

공식 출처에는 확인일을 적는다. 미실행 GPU 벤치마크를 실측으로 기록하지 않는다. 출판 시 장 색인, 공통 개념 두 개 이상, 읽기 노선, 양방향 링크를 함께 등록한다.

작업 중 갱신된 공통 규칙

최신 main의 닫힌 표지 기준을 확인하고 cover-art.svg를 별도 제작합니다. 320×150 정지 그림, 공통 cv-* 클래스, cover_meta와 제목·부제 형식을 적용합니다. 기존 펼침 애니메이션과 다른 장면으로 GPU 커널과 측정 시계를 그립니다.

동시 추가 도서와 지도 통합

원격에 추가된 RAG 책을 보존해 7권으로 통합합니다. 개념 지도의 기존 나선 탐색 반경이 새 배치를 찾지 못해, 같은 경계·겹침 판정 안에서 탐색 범위를 넓힙니다. 좌표를 수동 지정하지 않습니다. 팔레트는 여섯 색이므로 인접하지 않은 책의 rose 재사용을 허용하는 서가 진열 기준을 적용합니다.
