01 책의 약속

책 ID·제목probability-statistics · 확률과 통계 · 경보가 울렸다, 정말 고장일까 (폴더 books/probability/)
대상 독자비율과 평균은 알지만 "표본", "유의하다", "신뢰구간"이 나오면 막히는 사람. AI를 쓰거나 평가하면서 숫자를 얼마나 믿어야 할지 판단해야 하는 사람.
학습 후 할 일적은 데이터로 내린 결론이 얼마나 흔들리는지 계산하고, 경보·검사·실험 결과를 믿어도 되는지 기저율·신뢰구간·p값·검정력을 근거로 설명한다.
공통 사례한빛 공장의 모터 20대와 진동 센서. 담당자 서윤이 "오늘 경보 5번은 고장 신호인가"를 조사한다. 기준값: 센서별 하루 경보 확률 10%, 고장률 1%, 민감도 90%, 오경보율 5%.
끝의 과제새 공급업체 센서의 시험 자료(150센서·일 중 오경보 4번, 고장 재현 20번 중 19번 감지)를 보고 도입 여부, 부족한 증거, 다음 측정을 쓴다.
이야기 방식사건을 조사한다. 장마다 도구 하나를 얻고, 그 도구로 풀리지 않는 질문이 다음 장을 부른다.
범위·제외이산 확률, 이항분포, 요약 통계, 중심극한정리, 베이즈, 비율의 신뢰구간, 한쪽 이항검정, 우도와 교차 엔트로피. 연속분포의 일반 이론, 회귀분석, 다중검정, 베이즈 추론의 사전분포 설계, 인과추론은 다루지 않는다.
증거모든 수치 예시는 js/stats.js·js/inference.js로 다시 계산해 본문과 맞췄다. 개념 설명은 참고 자료 화면의 출처와 대조할 수 있다.

03 실험 명세

실험입력(기본값·범위)모델검증
coin · 1장p 0.5 (0.05~0.95), 던지기 1·10·100·1000번, 최대 5,000번씨앗 고정 난수(mulberry32)로 베르누이 시행, 누적 비율20,000번에서 p̂이 p의 ±0.015 이내
alarms · 2장n 20 (5~50), p 0.10 (0.02~0.50), 기준 5번이항분포 정확 계산 + 모의 날짜pmf 합 1, B(4,0.5)의 P(2)=6/16, 모의 평균≈n·p
outlier · 3장아홉 번째 값 5 (4~40 mm/s)평균·중앙값·표본표준편차(n−1)극단값 30에서 평균 +2.5 이상, 중앙값 변화 ≤ 0.1
clt · 4장모집단 3종, n 1 (1~50), 평균 최대 5,000개표본평균 시뮬레이션, 정규곡선 N(μ, σ/√n)세 모집단에서 평균들의 표준편차가 σ/√n의 ±8%
bayes · 5장고장률 1% (0.1~20%), 민감도 90%, 오경보율 5%베이즈 정리를 1,000대 자연 빈도로 표시사후확률 9/58.5, 네 칸 합 1,000, 경계값 0·1
interval · 6장진짜 비율 12% (2~50%), n 40 (10~500)Wilson 95% 점수 구간4,000번 반복 포함률 95% ± 2%p, 0~1 밖으로 나가지 않음
testing · 7장진짜 오경보율 5% (2~15%), 시험 60일 (20~500)한쪽 정확 이항검정 P(X ≤ k | 0.1), α = 0.05귀무가설에서 기각률 ≤ 6%, n=400 검정력 > 95%
likelihood · 8장n 60, k 3, 후보 q 0.10 (0.01~0.99)로그우도, 교차 엔트로피, 차이 1.92 기준선최댓값이 k/n, 교차 엔트로피 = −로그우도/n, 1.92 경계와 k = 0·n 경계값

그림 여덟 개는 개념 도식이며 실제 계산 결과가 아니다. 움직임은 CSS 애니메이션이고 prefers-reduced-motion에서 모두 멈춘다. 실험의 누적 애니메이션도 동작 줄이기 설정에서는 한 번에 끝난다. 모든 실험은 라벨이 붙은 슬라이더(키보드 화살표 가능), 초기화 버튼, 결과 문장(aria-live), 색 외의 표시(빗금·모양·✕·점선)를 갖는다.

04 검증 결과 (2026-10-08)

  • 수치 정확성: npm test --prefix books/probability 18개 통과(계산 14개, 장 경로·학습 흐름·교차 링크·카탈로그 4개). 본문의 모든 수치 예시를 계산 모듈로 다시 계산해 맞췄고, 이 과정에서 7장 p값(0.058 → 0.14)과 검정력(약 45% → 약 20%), 8장 손실값, 마지막 과제 p값을 바로잡았다.
  • 동작 확인: 로컬 서버에서 Chromium(Playwright)으로 tests/browser.cjs를 실행했다. 1280·390·320px에서 12개 경로가 모두 열리고 가로 넘침과 콘솔 오류가 없었다. 1280px에서 실험 8개마다 버튼 조작 후 결과 문장이 바뀌고, 키보드 화살표로 슬라이더가 움직이고, 초기화 후 처음 결과로 돌아오는 것을 확인했다. 진도 기록이 8개 실험 모두 저장되었다.
  • 구조 확인: python3 scripts/validate.py로 내부 링크·앵커(이 책 → AI Book 장 경로 포함)를 검사했다.
  • 화면 확인: 밝은 화면·어두운 화면에서 1장, 5장, 6장 실험과 320px 장 목록 열기·닫기를 스크린숏으로 확인했다.

06 화면 구성 · AI Book과 같은 틀 (2026-10-08)

사용자 요청에 따라 서가의 새 책들이 첫 책(AI Book)과 같은 레이아웃과 내용 구성을 갖도록 바꿨다. 책 사이 코드 의존을 만들지 않도록 books/ai/assets/style.css를 이 책의 assets/style.css 앞부분에 그대로 복사하고, 뒤에 이 책 전용 규칙(실험 차트, 그림 애니메이션, 예측·과제)을 붙였다.

  • 머리말·옆 목차·바닥글: AI Book과 같은 마크업. 기본은 어두운 화면이고 테마 선택은 bookshelf:probability-statistics:v1:theme에 저장한다. 옆 목차는 장 화면(body.reading)에서만 보이고, 760px 이하에서는 "목차" 버튼으로 연다.
  • 첫 화면: 소개와 작은 실험(js/home-lab.js, 센서 20대의 하루 경보 시뮬레이션)을 나란히 둔 hero, 흐름 다섯 칸, 사건 소개, 챕터 카드 3열(그림 썸네일 포함, 마지막 과제 카드 포함), 학습 경로 세 갈래, 참고 자료. #chapters와 #sources는 첫 화면의 해당 구역으로 이동한다.
  • 장 화면 순서: CHAPTER 머리 → 이번 장의 질문 → 먼저 개념 잡기(그림 N-1, 식, 숫자로 보기) → PREDICT FIRST → EXPERIMENT(무엇을 확인하나요?·결과 읽기 안내, 조작 | 그림 두 칸, 결과 문장, 직접 해 보기) → 실험의 가정 → 실험에서 본 것 → 새 상황에 옮기기 → CHECK YOUR UNDERSTANDING → 더 읽어 보기 → 아직 풀지 못한 질문 → 이전·다음. 학습 흐름 문제→예측→조작→관찰→설명→전이는 그대로 유지했다.
  • 실험 안내 문장과 "직접 해 보기" 과제는 js/guides.js에 실험 ID별로 둔다. 장 ID, 앵커, 진도 저장 키는 바꾸지 않았다.

05 확인하지 못한 것

  • 레이아웃 전환 후 Chromium 1280·390·320px에서 경로 12개, 실험 8개 조작·초기화, 가로 넘침 없음, 콘솔 오류 없음을 다시 확인했다. 밝은 화면은 1280px 한 화면(6장 실험)만 눈으로 확인했다.
  • 학습 효과: 실제 독자가 예측·설명·전이 문제를 풀 수 있게 되는지는 시험하지 않았다(L4 미확인).
  • Safari, Firefox, 실제 모바일 기기, 화면 읽기 프로그램, 저사양 기기 성능은 확인하지 않았다.
  • 참고 자료 링크 여섯 개는 집필 환경의 네트워크 제한으로 직접 열어 보지 못했다. 확인한 사람이 날짜를 남겨 주어야 한다.
  • 서가에서 책을 펼칠 때 보이는 대표 삽화(assets/shelf-illustration.svg)는 생성기 검사만 통과했고, 펼친 화면은 1280px 한 화면에서만 확인했다.
  • 요약은 루트 검증 기록에도 남겼다.
