#multimodal 더 깊이 보기(원본 04), docs/index.htmlOCR 대체 경로를 표·그림·손글씨 같은 내용 유형별로 둔다고 씀원본 04의 OCR 대체 경로는 수식·빽빽한 표용이고, 내용 유형은 평가 축“수식·빽빽한 표에 쓰는 OCR 대체 경로와 내용 유형별 평가”로 고침
#scale 더 깊이 보기(원본 45), docs/index.html“나쁜 묶음은 평소의 20배 노름”원본 45는 이전 최고치의 20배(4,200)“이전 최고치의 20배 노름”으로 고침
#rag 더 깊이 보기(원본 64), docs/index.html다섯 실패 중 “오래된 조각”원본 64의 실패 유형은 stale embeddings“낡은 임베딩”으로 고침
js/content.js 출처 목록(원본 84)“덜 거절”이 본문의 “과소 거절”과 다름같은 개념(under-refusal)을 본문은 과소 거절로 씀“과소 거절과 과잉 거절”로 통일
#verify 식 설명“실험의 k번 시도는 모두 끝까지 돌린다고 봅니다”가 실험과 모순passk 실험과 표지 실험은 통과하면 멈추는 차례 시도(math.js tryUntilPass)로 통과당 비용 = 시도당 비용 ÷ p를 계산해 k와 무관식의 해결당 비용은 k번을 모두 돌리는 경우이고 실험은 차례 시도라고 구분해 고침
#evals 더 깊이 보기 “과제 수를 늘리면”“200개부터 구간 전체가 0 위로”는 실제 경계로 읽힘같은 씨앗으로 계산하면 약 130개 안팎(102·110·120에서도 간헐적)부터 0 위로 올라옴. 200은 실험 선택지 가운데 첫 값“실험 선택지 가운데서는 200개부터(이 가정에서는 대략 130개 안팎부터)”로 고침

보류(고치지 않고 기록)

  • 원본 36의 “최소 10%” 하한은 레슨 36 연습 문제에 나오지만 권고 자체는 레슨 44의 것입니다. 책 서술이 크게 어긋나지 않아 그대로 둡니다.
  • DPO 길이 편향: 원본은 DPO가 짧은 답을 선호한다고 쓰지만, 책은 긴 답 쪽으로 기운다고 씁니다. 책의 서술이 문헌(Park et al. 2024, 길이 편향과 DPO)과 맞아 그대로 둡니다.
  • 원본 64가 LongRAG를 인용한 “재현율 35% 흔들림”은 책이 원본의 인용으로만 전합니다. 논문에서 직접 확인하지 못했습니다.
  • 원본 15는 여섯 층을 나열하고 “다섯 층”이라고 부릅니다. 책은 출력 필터와 사람 검토를 묶어 다섯으로 셉니다. 문제 없음으로 봅니다.
  • 원본 78은 옵티마이저 상태를 56GB와 28GB로 서로 다르게 적습니다. 책은 두 값 모두 쓰지 않습니다.

확인하지 못한 것

  • 검수 환경의 프록시 때문에 대부분의 외부 URL(arXiv·GitHub)을 curl로 열지 못했습니다. EAGLE-3과 MCP 인가 문서만 직접 열었고, 나머지 논문은 arXiv 번호와 제목을 알려진 문헌 정보와 대조했습니다.
  • 원본 레슨이 인용한 외부 목표 수치(예: 제품 지연 목표, 벤치마크 점수)는 원본에 적힌 값과 책의 값이 같은지만 확인했고, 각 수치의 1차 출처는 다시 확인하지 않았습니다.
  • 학습 효과는 검수 범위가 아닙니다.
