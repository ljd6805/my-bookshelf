기획과 검증 기록

이 문서는 독자가 읽는 본문이 아니라 책을 만들고 고칠 사람(사람·GPT·Claude)을 위한 기록입니다. 기획 결정, 장과 실험의 계약, 실제로 확인한 것과 확인하지 못한 것을 구분해 남깁니다.

책 기획서

책 ID·제목linear-algebra-world · 벡터와 행렬로 보는 세상 · 직접 움직이는 선형대수 (폴더 books/linear-algebra/)
독자좌표평면과 곱셈은 알지만 벡터·행렬이 AI와 그래픽에서 왜 계속 나오는지 감이 오지 않는 사람. 공식은 외웠어도 “행렬이 공간을 바꾼다”는 그림이 없는 상태.
끝의 행동데이터를 벡터로 적고, 내적·코사인으로 닮음을 계산하고, 행렬의 네 숫자를 보고 평면이 어떻게 변할지 예측해 설명한다. 행렬식·고유벡터·주성분이 무엇을 알려 주는지 판단한다.
공통 사례가상의 노래 여덟 곡(빠르기, 에너지; −3~3)과 독자의 취향 (1, 2). 마지막 장에서 셋째 특징(가사 비중)과 새 사용자 (1, 2, −2)가 추가된다. 데이터 원본: js/songs.js.
이야기 방식하나의 제품을 완성한다. 장마다 작은 노래 추천기의 부품(표현 → 닮음 → 점수 → 변환 → 되돌리기 → 요약 → 비선형 판단)을 하나씩 만든다.
범위2차원 중심의 벡터, 내적, 투영, 2×2 행렬, 합성, 행렬식, 역행렬·연립방정식, 고유벡터, 공분산과 PCA, 신경망 한 층(Wx + b, ReLU). 3차원은 계산만, 고차원은 개념만.
다루지 않는 것행렬 분해(LU, QR, SVD)의 계산 절차, 일반 n×n 행렬식 전개, 복소 고윳값, 벡터 공간의 공리적 정의, 학습(경사하강법) 과정.
증거11장 마지막 과제: 3차원 데이터에서 무엇을 바꿀지·왜·부족한 증거를 쓰고, 예시 답안과 채점 기준으로 비교한다. 각 장의 예측 문제와 이해 확인 두 개.

구조 결정(2026-10-08 개편): 사용자 요청에 따라 서가의 첫 책인 AI Book(books/ai/)과 같은 화면 구성으로 바꿨다. index.html 한 페이지가 해시 경로(#home, #chapters, #sources, #vectors … #challenge)로 표지와 11개 장을 보여 준다. 머리말(서가로·전체 목차·참고 자료·밝은/어두운 화면·모바일 목차), 장을 읽을 때의 왼쪽 사이드바, 표지 순서(히어로 실험 → 흐름 → 공통 사례 → 전체 챕터 → 학습 경로 → 참고 자료), 장 순서(머리말 → 먼저 개념 잡기 → EXPERIMENT → 혼동하지 마세요 → 확인 문제 → 더 읽어 보기 → 이전·다음)를 AI Book에 맞췄다. 이 서재의 흐름(문제 → 예측 → 조작 → 관찰 → 설명 → 전이)을 지키려고 첫 실험 안에 예측을, 실험 뒤에 ‘실험 결과 읽기’·‘새 상황에 써 보기’·‘남은 질문’을, 다음 장 링크에 이동 이유를 둔다.

파일: 본문은 js/content.js(장마다 장 지도 5칸·개념 그림·공식·예측·관찰·숫자 예·이해 확인·전이·혼동 주의·더 깊이·확인 문제·참고 자료·남은 질문·다음 장 이유), 실험 마크업과 안내 상자(무엇을 확인하나요?·비교 예제·결과 읽기)는 js/lab-views.js, 화면은 js/helpers.js·js/page-home.js·js/page-chapter.js·js/app.js가 만든다. 계산(linalg.js)과 실험 코드(labs-*.js)는 개편 전과 같다. 이전의 장별 파일(vectors.html 등)은 없어졌고 카탈로그의 장 링크는 books/linear-algebra/#vectors 형식으로 바꿨다. 장 ID는 그대로다. JavaScript가 꺼진 환경에서는 본문이 보이지 않는다(AI Book과 같은 제약, noscript 안내).

  • python3 scripts/validate.py와 python3 scripts/build_catalog.py --check: 오류 0개(실행 결과는 PR 설명에 기록).

브라우저 확인 (로컬 Chromium, Playwright)

tests/browser.cjs로 표지와 11개 장을 1280px·320px에서 열어 콘솔 오류 0, 가로 넘침 0, 머리말의 서가 버튼(높이 36px 이상, 화면 안), 실험 준비를 확인했다(24/24). 1280px에서는 실험마다 비교 예제 버튼을 차례로 눌러 결과 문장에 본문의 검증값(예: 1장 (1.00, 1.50)·(0.00, 0.00), 6장 3.18·0.00·−2.25, 7장 (2.00, 1.50)·(−4.75, 15.00), 9장 55%·94%·6%)이 나오는지, ‘실험 초기화’로 처음 문장으로 돌아오는지, 키보드 화살표로 슬라이더가 움직이는지, 확인 문제의 정답 버튼이 ‘정답입니다.’를 보이는지 확인했다. 표지·1·5·9·11장은 1280px·390px 화면 캡처로 배치를 눈으로 확인했다.

확인하지 못한 것과 한계

  • Safari·Firefox, 실제 모바일 기기, 화면 읽기 프로그램, 저사양 기기의 애니메이션 성능은 검사하지 않았다. 320px 확인은 데스크톱 Chromium의 창 폭 조절이다.
  • 그림을 끌어서 B를 옮기는 2장의 터치 조작은 코드만 확인했다. 같은 값을 슬라이더로 조작할 수 있다.
  • 그림자 애니메이션(3장)에서 점이 겹치면 이름표도 겹친다. 순위는 표로 읽는다.
  • 노래와 특징 점수는 모두 설명용 가상 데이터다. 외부 사실 주장(검색 엔진, GPS, PageRank류 계산)은 원리 수준의 예시로만 썼으며 수치를 인용하지 않았다.
  • 서가 미리보기의 삽화(assets/shelf-illustration.svg)는 CSS 애니메이션이며, 서가 쪽 동작 줄이기 설정과 prefers-reduced-motion에서 변환 후 장면으로 멈춘다.
