LLM 직접 만들기 · 제작 문서책 읽기

LLM 직접 만들기 · 토크나이저에서 정렬과 서빙까지 · 제작 문서

「AI 엔지니어링 처음부터」 시리즈 11권의 기획, 원본 레슨 대응, 구현, 검증 기록입니다. 원본은 공개 저장소 rohitg00/ai-engineering-from-scratch(MIT, 2026 Rohit Ghumare)의 phases/10-llms-from-scratch 가운데 24개 레슨(01~22, 25, 34)입니다. 개념·순서·실험 아이디어만 참고하고 문장과 코드는 새로 썼습니다. 작성·확인일 2026-10-08.

1. 기획

항목결정
독자트랜스포머와 경사하강은 알지만, LLM 하나를 처음부터 끝까지 만들 때 어떤 단계가 어떤 순서로 있고 단계마다 무엇이 비용과 품질을 정하는지는 설명하지 못하는 개발자와 학생.
끝의 행동출시 직전 한 단계가 실패했을 때, 의존 그래프에서 다시 해야 할 단계와 재사용할 체크포인트를 고르고, 그 판단의 근거(메모리·계산량·평가 결과)를 숫자로 말할 수 있습니다.
공통 사례"서재봇": 서재의 책과 실험을 추천하는 작은 LLM. 1장의 병합표 학습과 3장의 바이그램 학습은 서재봇 소개문으로 실제 계산하고, 4~11장은 8B 크기의 서재봇을 가정해 메모리·정렬·평가·서빙 결정을 계산합니다.
이야기 방식하나의 제품을 완성한다. 토큰과 데이터 → 사전학습과 규모 → 정렬 → 평가와 서빙의 네 묶음으로 단계를 하나씩 붙이고, 12장에서 열한 단계를 출시 매니페스트로 묶어 되돌리기 범위를 계산합니다.
겹침 처리AI Book의 토큰·생성·어텐션·정렬, LLM GPU 책의 가중치 메모리·KV 캐시·모델 카드, LLM 성능 책의 병렬화·배칭은 짧게 요약하고 cross 링크로 보냅니다. 분량은 원본에만 있는 바이트 BPE 학습, MinHash 중복 제거, Chinchilla 배분, ZeRO·재계산·GPipe, 손실 마스크, DPO·GRPO, ELO, 추측 디코딩, 오픈 모델 config 읽기, 파이프라인 매니페스트에 씁니다.
증거BPE, MinHash·LSH, 패킹, 바이그램 학습, 양자화, GRPO 집단, ELO는 브라우저 안의 실제 계산입니다(작은 말뭉치·작은 행렬·고정 시드). Chinchilla, ZeRO 메모리, 활성값 재계산, GPipe 거품, DPO 손실, 추측 디코딩, 모델 파라미터·KV 캐시는 원본 레슨과 인용 논문의 공식을 계산한 값입니다. SFT 토큰 손실값과 12장의 단계별 시간은 비교용 가정값이며 화면에 밝혔습니다.
마지막 과제12장: 평가 게이트에서 SFT·DPO·양자화 중 하나가 실패했을 때 다시 할 단계와 시간을 의존 그래프로 계산하고, 사전학습처럼 비싼 단계는 체크포인트로 재사용하는 판단을 설명합니다.

2. 원본 레슨 대응표

24개 레슨을 모두 12장에 배치했습니다. 19강(DualPipe)은 5장 병렬화, 34강(활성값 재계산)은 4장 메모리, 15·22·25강(추측 디코딩·Hogwild)은 10장 서빙, 14·16~18·20·21강(오픈 모델 구조)은 11장으로 묶었습니다.

3. 구현

  • 파일: js/math.js(모든 계산, DOM 없음), js/content.js(모든 글), js/visual.js(공통 UI), js/figures.js(장마다 움직이는 개념 그림 12개), js/labs-data.js(1~2장), js/labs-train.js(3~5장), js/labs-align.js(6~9장), js/labs-serve.js(10~12장), js/home-lab.js(표지 실험), js/lab-guides.js, js/app.js. 전역 접두어는 A11입니다.
  • 실제 계산: 바이트 단위 BPE 학습(동률은 먼저 나온 쌍), 낱말 3-gram MinHash와 LSH 확률, 패딩·패킹 활용률, 글자 바이그램 로짓 표의 전체 배치 경사하강, 16×64 가중치의 대칭 양자화(텐서·채널 배율), GRPO 집단 이점과 신호 없음 확률(식과 500회 표본), 고정 시드 ELO 시뮬레이션. UTF-8 인코딩·디코딩은 직접 구현해 실행 환경과 무관하게 같은 결과를 냅니다.
  • 공식 계산: Chinchilla 적합식(E 1.69, A 406.4, B 410.7, α 0.34, β 0.28)과 6ND, ZeRO의 16Ψ 셈, Korthikanti 등의 층당 활성값 s·b·h·(34 + 5·a·s/h), GPipe 거품 (P−1)/(M+P−1), DPO 손실 −log σ(β·m), 추측 디코딩 기대 토큰 (1 − αN+1)/(1 − α), 공개 config로 계산한 전체·활성 파라미터와 토큰당 KV 바이트, NSA 키 수.
  • 가정과 한계: 말뭉치는 수백 바이트, 모델은 글자 바이그램 수준이며 결과는 한 시드의 한 번 실행입니다. 메모리·속도는 실제 장비에서 재지 않았습니다. 모델 이름과 공개 수치는 원본 커리큘럼 기준(확인일 2026-10-08)입니다.
  • 서가 삽화: assets/shelf-illustration.svg는 바이트가 토큰으로 합쳐지고, 손실 곡선이 그려지고, 정렬·서빙을 거쳐 답이 나가는 시각적 비유입니다. @keyframes 7개, prefers-reduced-motion과 html[data-motion=reduce]에서 멈춥니다. 표지 그림 assets/cover-art.svg는 출시 매니페스트의 단계 그래프를 그린 정지 그림입니다(cv-* 클래스만).
  • 서재 등록 제안: registration.json(장 색인, 개념, 읽기 노선 단계, 들어오는 링크).

실험L1 접근L2 반응L3 모형L4 학습
bpe확인확인병합 후 디코딩이 원문 바이트와 같음, 한국어 398바이트 → 병합 49회 뒤 149토큰, 영어 표로 한국어 문장 53토큰미확인
minhash확인확인같은 집합 Jaccard 1, k가 클수록 추정 오차 감소, LSH 확률 단조 증가미확인
packing확인확인L 1,024에서 패딩 51%·패킹 92%, 패킹 활용률 ≥ 패딩미확인
nextchar확인확인시작 손실 ln 57, 학습률 20에서 400회 뒤 0.925, 바닥 0.914 아래로 내려가지 않음미확인
chinchilla확인확인5.88×10²³에서 최솟값 N ≈ 32.4B, 6ND = C 불변미확인
trainmem확인확인16Ψ, ZeRO 3단계 1/N, 70B 최소 14장미확인
ckpt확인확인층당 활성값 식, 선택적 재계산이 5as/h 항만 제거미확인
bubble확인확인일정표에서 센 거품 = (P−1)/(M+P−1)미확인
lossmask확인확인응답만 세는 손실이 지시문 길이와 무관(1.15)미확인
dpo확인확인m = 0에서 ln 2, 손실이 m에 대해 감소미확인
grpo확인확인이점 평균 0, 신호 없음 확률 식과 표본 비율 근접미확인
elo확인확인점수 합 보존, 기대 승률 식미확인
contam확인확인문항 어절 수 17·21·19·14·20·10, 전체 묶음 13-gram 5/31 실패, 복사본 지운 묶음 13-gram 0/31 통과(바꿔 쓴 문항 2개 놓침)·8-gram 9/59, 문항 2의 겹친 조각 n = 8~13에서 5·4·3·2·1·0, 학습 조각이 늘면 겹침이 줄지 않음미확인
quant확인확인4비트 SNR 텐서 11.3dB·채널 21.4dB, 비트가 늘수록 오차 감소미확인
specdec확인확인α → 0이면 기대 토큰 1, N = 1 식미확인
config확인확인Mixtral 46.70B·12.88B, DeepSeek-V3 671.03B·37.55B, Llama 3 8B 128K KV 17.2GB미확인
rollback확인확인SFT 실패 7단계 246시간, 양자화 2단계 6시간미확인

확인하지 못한 것: 학습 효과(L4)는 실제 독자로 시험하지 않았습니다. 메모리·속도 수치는 실제 GPU에서 재지 않았고, 공개 모델 수치는 config 공식 계산이며 모델 제작사의 발표값과 작은 항목(편향, 정규화 등)에서 다를 수 있습니다. 화면 낭독기로 읽는 경험과 실제 모바일 기기는 확인하지 않았습니다. 사실·수치는 별도 검수자가 원본과 인용 논문에 대조했습니다.

  • 예측: 상세 절의 질문대로 "n을 8로 낮추면 겹침률이 오르고, 새로 걸린 문항은 다 오염일 것"이라고 예측하고 시작했습니다.

  • 설명: 이 지점에서 독자는 "n을 줄이면 놓침이 줄고 헛경보가 는다, 13-gram 통과는 오염 없음이 아니다"를 n별 겹침률 줄(놓침·헛경보 표시)을 근거로 말할 수 있습니다. 전이는 12장 게이트에서 같은 기준으로 HOLD를 판단하는 일입니다.
  • 걸린 곳(고치지 않음): ① 복사본을 지운 묶음에서 "문항 1 · 그대로 복사"가 ✓로 나와, 처음 보는 독자는 검사기가 복사본을 놓쳤다고 읽을 수 있습니다. 결과 문장의 놓침 수(2)가 문항 2·3만 세므로 구분은 되지만, 다음 보충 때 문항 이름 옆에 "원본 조각이 이 묶음에 없음"을 더할 만합니다. ② 전체 묶음 n ≥ 11에서 복사본인 문항 6이 검사 불가로 빠지는데 놓침 수에는 들지 않습니다(검수 회차의 관찰과 같음). 목록에 "– 검사 불가"가 보여 오류는 아닙니다.
  • 리안의 점검: 실험 블록은 다른 실험과 같은 U.setup·U.result 형식(설명, 예제 세 개, 조작, 그림, 결과 문장, 초기화)입니다. 계산은 math.js의 contamination이 DOM 없이 하고 labs-align.js는 읽고 그리기만 합니다. 입력 셋 모두 라벨이 있고, 방향키로 n이 움직이며, "실험 초기화"가 n = 13·전체 묶음으로 돌아갑니다. 잘못된 n은 "입력 오류" 문장을 냅니다(단위 테스트로 확인). 상태는 색 말고도 ✕·✓·–와 ▲, 칩의 aria-label("문항 1의 어절 17개 가운데 … 17개")로 보입니다. 1280·320px에서 문서 폭 = 화면 폭(가로 넘침 없음), 콘솔 오류 0. 이 실험에는 새 그림이 없고, 막대그림은 "문항별 겹침률"을 보여 준다는 한 줄 설명이 있습니다.
