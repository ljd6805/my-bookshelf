검색과 RAG · 제작 문서

《검색과 RAG · 질문에서 근거까지》의 기획, 구현, 검증 기록입니다. 2026-10-08 사용자가 지식관리 분야 첫 책으로 승인했고, 같은 날 지식 그래프 책과 함께 추가했습니다.

1. 쓰기 전 다섯 가지

독자사내 문서나 개인 노트를 검색·RAG로 연결해 보려는 학생과 개발자. 벡터가 숫자 목록이라는 정도만 알면 됩니다.
끝의 행동새 질문 묶음을 받으면 검색 방식·조각 크기·α·후보 수·문턱을 정하고, 그 선택을 평가 지표와 보류 결과로 설명할 수 있다.
공통 사례가상의 한빛시립도서관 이용 안내 문서 13개(이용 규정 10문장 포함)와 질문 13개(답 없는 질문 3개). 모든 장이 같은 문서와 질문을 씁니다.
범위검색 단계(역색인, BM25, 조각, 임베딩, 혼합, 평가, 재순위)와 입력 조립·답 보류. 언어 모델 생성 자체, 학습된 임베딩·재순위 모델, 벡터 DB 색인 구조(HNSW 등)는 범위 밖입니다.
증거모든 순위와 지표를 브라우저에서 실제로 계산하고, 대표값을 tests/math.test.cjs로 고정했습니다.
이야기 방식제품을 완성한다: 안내 도우미를 한 단계씩 고쳐 마지막에 “모르면 보류”하는 정책을 정합니다.

2. 구조

4부 10장(찾기 1~4, 의미 5~6, 평가 7~8, 답하기 9~10), 장마다 실험 하나, 확인 문제 하나, 움직이는 개념 그림 하나. 화면 구조는 책 구성 표준을 따르며 파일 분리는 LLM 시스템 책과 같습니다(js/math.js 계산, content.js 본문, labs-*.js 실험, figures.js 개념 그림, home-lab.js 표지 실험).

실험의 성격: 역색인·BM25·조각·혼합·평가 지표·컨텍스트 예산·문턱 판정은 실제 계산입니다. 임베딩은 손으로 정한 7차원 교육용 모형, 재순위는 학습하지 않은 교육용 모형, 1장의 “근거 없는 답”은 미리 적은 시나리오입니다. 토큰은 어절 × 1.5 어림값, KV는 LLM 시스템 책의 가상 8B 모델(토큰당 128 KiB)입니다.

4. 검증 (2026-10-08)

구조 확인: npm test --prefix books/rag 30개 통과(계산 23개, 경로·필드·링크 7개). 루트 python3 scripts/validate.py, build_catalog.py --check 통과.

동작 확인: tests/browser.cjs로 Chromium 1280·390·320px에서 표지와 10개 장 38화면, 실험 30회(폭마다 10개)의 예제 버튼·모든 입력의 경계값·초기화·확인 문제 정답/오답을 조작해 오류·NaN 없음, 가로 넘침 없음, 서가로 버튼 표시를 확인했습니다. 결과: browser-results.json.

서가 확인: 서가에서 책을 꺼내 펼쳐 1280·390·320px 모두 대표 삽화가 실행 중 애니메이션 4개로 움직이는 것과(돋보기 이동, D2 강조, 근거 조각 이동, 답 말풍선) 가로 넘침이 없음을 확인했습니다. 책등은 “검색과 RAG / 지식관리”로 잘리지 않습니다.

수치 정확성: BM25 손계산, 조각 수 공식, 코사인, P@k·R@k·MRR 정의, 재순위 후보 한계, KV 128 KiB, 문턱 판정 합계 13을 테스트로 고정했습니다. 안내 상자·본문의 숫자(MRR 0.76/0.83/0.93, 문턱 0에서 9개 맞고 4개 틀림 등)는 테스트 값과 같습니다.

실험 확인 수준: 10개 실험 모두 L1 접근(라벨·키보드·글 결과), L2 반응(입력마다 결과 변화), L3 모형(계산 테스트)까지 확인했습니다. L4 학습 효과는 독자 검증이 없어 미확인입니다.

확인하지 못한 것: Safari·Firefox·실기기·화면 낭독기, 학습 효과(L4), 참고 자료 URL은 네트워크 제한으로 이번 세션에서 다시 열어 보지 않았습니다(서지 정보로 작성). 닫힌 표지(cover-art.svg)는 표지 규칙 PR이 병합된 뒤 서가에서 다시 확인해야 합니다.

5. 2026-10-12 보충

  • 공통: 10개 장마다 전이 문항(transfer, “다른 상황에 써 보기”)을 확인 문제 블록 안에 더했습니다. 블록을 새로 만들지 않아 일곱 블록 순서는 그대로입니다. 보기 순서는 화면에서만 돌려(choiceOrder) 확인 문제의 정답은 장 순번 % 3번째 자리, 전이 문항의 정답은 그다음 자리에 오고, 데이터의 정답 번호와 data-answer·data-transfer 값은 원래 번호를 유지합니다. 장 머리의 문구는 “확인 문제 2개”가 됩니다.
  • 5장 #embedding: 깊이 읽기 “문서가 13개가 아니라 100만 개라면: 근사 최근접 탐색”을 더했습니다. 전수 비교 비용(1,000,000 × 768 × 4 byte ≈ 3.07 GB, 질문 하나에 곱셈·덧셈 약 7.68억 번), IVF·HNSW 근사 색인과 그 대가, 7장 재현율@k로 근사 색인을 평가하는 법을 다룹니다. 768차원은 예로 든 값으로 표시했습니다. 출처 HNSW(arXiv 1603.09320), FAISS(arXiv 1702.08734), FAISS wiki “Faster search”를 2026-10-12에 원문 페이지로 확인했습니다. 새 실험은 없습니다(실험 10개 유지).
  • 검산: 전이 문항의 IDF(ln(1 + 990.5/10.5) ≈ 4.56, ln(1 + 600.5/400.5) ≈ 0.92), 조각 수 ⌈18/2⌉ = 9, 코사인 0.8, 혼합 점수(α 0.7: 0.72·0.52, α 0.3: 0.48·0.68), KV 1,300 × 128 KiB = 162.5 MiB·50명 7.93 GiB, 마지막 과제 문턱 비용(0.50 → 6, 0.60 → 4, 0.80 → 5)을 책 코드와 따로 계산했습니다.
  • 검증: npm test, python3 scripts/validate.py(0 오류), python3 scripts/build_catalog.py --check(통과), tests/browser.cjs(1280·390·320px에서 모든 장의 확인 문제·전이 문항 정답/오답 클릭, 실험 예제·경계값·초기화, 가로 넘침, 서가로 버튼)를 실행해 모두 통과했습니다.
  • 확인하지 못한 것: 전이 문항이 실제로 새 상황 적용을 돕는지(L4 학습 효과)는 독자로 확인하지 않았습니다. 집필자가 자기 글을 검수하지 않으므로, 이번 보충은 다른 세션의 팩트·출처 검수 새 회차가 필요합니다. 개념 그림(F.embedding)에 전수·근사 비교 막대는 더하지 않았습니다.
