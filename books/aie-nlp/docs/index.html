자연어 처리 · 제작 문서

「AI 엔지니어링 처음부터」 시리즈 06권 《자연어 처리 · 단어 세기에서 문장 이해까지》의 기획, 원본 레슨 대응, 구현, 검증을 한곳에 모았습니다. 작성일 2026-10-08. 원본은 rohitg00/ai-engineering-from-scratch(MIT)의 Phase 5 · NLP — Foundations to Advanced이며, 원문과 코드를 옮기지 않고 개념과 순서, 실험 아이디어만 참고해 새로 썼습니다.

1. 기획

  • 독자: 파이썬과 기초 확률은 알고, LLM API도 써 봤지만 그 아래에 있는 토큰화·가중치·태깅·평가 지표가 왜 그렇게 생겼는지는 설명하기 어려운 사람.
  • 끝의 행동: 새 언어나 긴 문서가 들어온 텍스트 시스템을 보고, 어느 단계(토큰화, 검색, 청킹, 평가)를 바꿔야 하는지 고르고 그 판단에 부족한 증거를 말할 수 있습니다.
  • 공통 사례: 온라인 서점 “마루책방”의 고객 문의함. 문의 여덟 통, 학습 리뷰 열두 개, 약관 열두 문장, 다섯 턴 배송 변경 대화가 모든 장에 다시 나옵니다.
  • 이야기 방식: 하나의 제품을 완성한다. 장마다 문의 도우미에 도구 하나(토큰화, 가중치, 벡터, 주제, 분류, 태깅, 언어 모형, 번역, 청킹, 연결, 대화 상태)를 더하고, 마지막 장에서 해외 문의와 긴 약관이라는 새 상황에 내놓습니다.
  • 범위: 원본 Phase 5의 레슨 29개 전부. 토큰·임베딩·어텐션·RAG의 기초 그림은 AI Book, 코사인 유사도는 선형대수 책에 맡겨 짧게 요약하고 링크로 보냅니다. 정보 검색, 청킹, 관계 추출, 개체 연결은 NLP 관점에서만 짧게 다루며, 아직 없는 시리즈 권(검색과 RAG, 지식 그래프)으로는 링크하지 않았습니다.
  • 증거: 실험 16개 중 15개는 규칙과 수식을 브라우저에서 실제로 계산합니다. 단어 벡터, 주제 분포, HMM 확률표, 약관 문장 길이, 개체 사전 확률은 교육용 가정값이고, 다섯 턴 대화는 시나리오입니다. JSON 유효율은 토큰 독립 가정의 교육용 모형이며, 긴 문맥 바늘 찾기는 원본이 설명한 경향을 흉내 낸 교육용 모형으로 측정값이 아닙니다. 각 결과 문장에 어느 쪽인지 적었습니다.

부 구성: 표현(1~3장) · 분류(4~6장) · 생성(7~9장) · 연결과 검증(10~12장).

  • 팩트·출처 검수: 책을 쓰지 않은 검수 에이전트가 2026-10-08에 사실·수치·실험·용어·출처를 확인하고 10건을 고쳤습니다. 결과와 수정 내역은 팩트·출처 검수 기록에 있습니다.
  • 계산 검사: npm test --prefix books/aie-nlp 통과(21개 검사). 계산 함수마다 대표값·경계값·불변 조건을 확인합니다(예: 평활 없는 IDF는 df=N에서 0, BPE 토큰 수 단조 감소, 주제 비율 합 1, k=0의 처음 보는 쌍은 무한대, 어텐션 가중치 합 1, 조각 경계 연속성, JSON 유효율 p=0·1 경계).
