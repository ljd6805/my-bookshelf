AI 인프라와 운영 · 제작 문서

「AI 엔지니어링 처음부터」 시리즈 18권 《AI 인프라와 운영 · 모델 서버에서 운영 장부까지》의 기획, 원본 레슨 대응, 구현, 검증을 한곳에 모았습니다. 작성일 2026-10-08. 원본은 rohitg00/ai-engineering-from-scratch(MIT)의 Phase 17 · Infrastructure and Production입니다. 원문과 코드를 옮기지 않았고, 개념과 순서만 참고해 새로 썼습니다.

1. 기획

  • 독자: LLM을 API로 불러 본 적은 있지만, 직접 모델 서버를 올리고 비용과 지연, 사고를 책임져 본 적은 없는 엔지니어. vLLM, goodput, 카나리라는 이름은 알아도 “지금 우리 서비스에 어느 손잡이를 돌려야 하는지” 숫자로 말하기 어려워합니다.
  • 끝의 행동: 운영 보고 하나를 받고, 원인을 어느 장의 변수(웜 풀, 프롬프트 순서, 청크 프리필, 라우팅)에서 찾을지 고른 뒤, 같은 계산을 다시 돌려 처방이 실패한 지표를 실제로 움직이는지 확인합니다.
  • 공통 사례: 다온의 상담 챗봇 누리봇. 쇼핑몰·병원 예약·유럽 매장 세 고객사가 하루 약 5만 건을 보내고, 요청마다 공통 접두부 2,000토큰·고객별 내용 500토큰·답 200토큰을 씁니다. 70B 모델을 H100 80GB에 올리고, 목표는 TTFT 800ms·TPOT 25ms·전체 3,000ms입니다.
  • 이야기 방식: 하나의 제품을 완성한다. 장마다 누리봇 운영에 필요한 결정 하나(어디서 돌릴지, 어떤 형식으로 담을지, 엔진을 어떻게 설정할지, 무엇을 잴지, 어떻게 빠르게 할지, 어디로 보낼지, 언제 늘릴지, 청구서를 어떻게 줄일지, 무엇을 지킬지, 어떻게 바꿀지, 사고에 어떻게 대비할지)를 계산으로 내리고, 마지막 장에서 월요일 아침의 운영 보고 세 가지를 진단합니다.
  • 범위: 원본 Phase 17의 레슨 28개 전부. 페이지 KV, 연속 배치, 지표 정의, 가중치 형식처럼 서재의 LLM 시스템(books/llm-gpu)·LLM 성능(books/llm-performance) 책이 깊게 다룬 내용은 한 문단으로 줄이고 그 장으로 링크합니다. 대신 운영 결정과 비용, 확률로 따지는 배포·사고 대응에 분량을 씁니다.
  • 증거: 실험 18개는 모두 브라우저에서 js/math.js의 함수로 계산합니다. 실제 계산인지, 시드를 고정한 시나리오인지, 교육용 가정값이 무엇인지를 결과 문장마다 밝힙니다. 가격·제품 상태·버전은 원본 커리큘럼 기준(확인일 2026-10-08)으로만 쓰고 현재 가격표로 제시하지 않습니다.

3. 구현

  • 파일 구조: js/math.js(계산만, DOM 없음) · js/content.js(장 글·출처·실험 설명) · js/labs-serve.js(1~6장 실험) · js/labs-ops.js(7~12장 실험) · js/figures.js(장마다 움직이는 그림) · js/home-lab.js(표지 실험) · js/lab-guides.js(예제와 결과 읽기).
  • 전역 접두어 A18, 서가 삽화 접두어 a18-ill-, 진도 키 bookshelf:aie-18-production:v1:progress.
  • 교육용 가정값: GPU 시간당 4달러, 70B FP8 한 대 처리량 2,300 tok/s(원본 레슨 04의 2,200~2,400 범위), HBM 대역폭 3,350GB/s, 프리필 초당 4만 토큰과 디코드 한 반복 7ms(원본의 “32K 프롬프트 약 800ms”에 맞춤), 링크 속도(원본의 “4K 프롬프트 20~80ms”에 맞춤), API 단가(원본 레슨 15의 예시 단가).

  • 난수는 mulberry32에 시드를 고정해 화면과 테스트가 같은 값을 냅니다.
