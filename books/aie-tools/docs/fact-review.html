#client 본문 둘째 문단·“옛 방식으로 내려가도 되는 경우” 3번·확인 문제 (js/content.js)원본 레슨 08을 따라 server/discover의 시간 초과·모르는 오류를 “아무것도 증명하지 않는 모호한 신호”로 보고, 허용 목록에 없는 서버는 실패시키는 것이 정답이라고 가르침MCP 2026-07-28 stdio 전송의 Backward Compatibility: “The server returns any other error, or does not respond within a reasonable timeout: the server is legacy. Fall back to the initialize handshake.” 버전 관리 페이지의 호환 표도 같음명세 규칙(알려진 최신 오류면 내려가지 않고, 그 밖의 오류·시간 초과면 initialize로 내려감, 특정 코드에 묶지 않음)을 기준으로 다시 쓰고, 허용 목록은 원본이 권하는 더 엄격한 운영 정책으로 구분해 소개. 확인 문제는 -32022를 받았을 때 supported의 버전으로 다시 보내는 문제로 바꿈
