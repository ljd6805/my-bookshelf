도구와 프로토콜 · 제작 문서

「AI 엔지니어링 처음부터」 시리즈 14권 《도구와 프로토콜 · 함수 호출에서 MCP와 스킬까지》의 기획, 원본 레슨 대응, 구현, 검증을 한곳에 모았습니다. 작성일 2026-10-08. 원본은 rohitg00/ai-engineering-from-scratch(MIT)의 Phase 13 · Tools & Protocols이며, 원문과 코드를 옮기지 않고 개념과 순서만 참고해 새로 썼습니다. MCP 규칙은 원본 레슨이 기준으로 삼은 2026-07-28 개정판을 따르며, 원본 커리큘럼 기준(확인일 2026-10-08)입니다.

1. 기획

  • 독자: LLM API를 불러 본 적은 있지만, 모델이 도구를 부르는 과정과 MCP 서버를 운영할 때 생기는 실패(버전·헤더 불일치, 숨은 상태, 캐시 누출, 재시도 변조, 토큰 오용, 서술자 변경)를 계약 단위로 나눠 설명하기 어려운 사람.
  • 끝의 행동: 노트 비서의 이상 보고 한 줄을 받고, 어느 계약(선 위 기록, 서술자 고정, 토큰 주장, 트레이스, 멱등 키 장부)부터 확인할지 순서를 세우고, 부족한 증거를 되물을 수 있습니다.
  • 공통 사례: 팀 회의 노트를 찾고 요약하고 정리하는 노트 비서. notes_search·notes_delete·export 도구, notes 서버와 tasks 서버, 지우와 민호 두 사용자가 모든 장에 다시 나옵니다. 장마다 첫 문단이 앞 장에서 노트 비서에 더한 계약으로 시작합니다.
  • 이야기 방식: 하나의 제품을 완성한다. 한 앱 안의 함수 호출에서 시작해 MCP 서버, 되묻기, 긴 작업, 보안, 게이트웨이, 스킬로 계약을 한 겹씩 더하고, 마지막 장은 다섯 가지 이상 보고라는 새 상황에 그 계약들을 씁니다.
  • 범위: 원본 Phase 13의 레슨 31개 전부. 에이전트 고리의 큰 그림은 AI Book #agents에, 검색 문맥 구성은 검색 증강 책 #context에, 지연 지표는 LLM 성능 책에 맡기고 링크로 보냅니다. 이 책은 프로토콜 계약과 그 계약을 검증하는 공학적 판단에 분량을 씁니다.
  • 증거: 실험 16개 중 다수는 원본 레슨의 규칙을 브라우저에서 실제로 계산합니다(JSON Schema 부분 검사, 순차·병렬 공식, 독립 재시도 확률, 설명 린트 규칙, 요청 검사 순서와 오류 코드, 캐시 키와 유효 시간, requestState 검사 순서와 nonce, 두 시계, 키 정렬 JSON과 해시, 토큰 검사 순서, 목록 예산, 혼동 행렬과 출시 기준). 도구 지연 일부·스팬 지연·토큰 크기·점검 시간은 교육용 가정값이고, 캐시 요청 순서·작업 이야기·라우팅 점수·사고 원인은 미리 정한 시나리오입니다. 각 결과 문장에 어느 쪽인지 적었습니다.

부 구성: 도구 호출(1~2장) · MCP 프로토콜(3~7장) · 보안과 운영(8~10장) · 스킬과 종합(11~12장).

4. 검증

검증일 2026-10-08. 실제 MCP 서버·클라이언트·인가 서버·모델을 실행한 검증은 아닙니다.

  • 계산 검사: npm test --prefix books/aie-tools 통과. 계산 함수마다 대표값·경계값·불변 조건을 확인합니다(예: 도구 3개 순차 1800ms·병렬 800ms, 병렬 ≤ 순차, limit 1·20 경계, 헤더 불일치가 버전 검사보다 먼저, 실패 검사 뒤는 모두 건너뜀, private 범위의 누출 0, 변조된 재시도는 변경·nonce 없음, 모든 시계 결과 ≤ 2000ms, 정렬 JSON 정규화, 혼동 행렬 합 16).
  • 브라우저 검사: tests/browser.cjs로 1280·390·320px에서 표지와 12장을 열고, 실험 16개마다 예제 버튼·입력 최솟값과 최댓값·선택 상자 모든 값·초기화를 눌러 결과 문장에 NaN·undefined가 없는지, 확인 문제 반응, 가로 넘침, 서가로 버튼, 목차, 콘솔 오류 없음을 확인했습니다. 결과는 docs/evidence/browser-results.json.
  • 눈으로 확인: 표지, 개념 그림, 모바일 실험 스크린숏을 열어 글자 겹침·잘림을 보았습니다.
  • 팩트·출처 검수: 집필하지 않은 검수 에이전트가 사실·수치·실험·용어·출처를 MCP 2026-07-28 공식 명세 등과 대조한 기록은 팩트·출처 검수 기록에 있습니다.

확인하지 못한 것: L4(대표 독자가 새 조건에서 설명하는지)는 사람 검토가 필요해 하지 못했습니다. 서가에서 책을 펼쳐 삽화가 움직이는지는 서재 등록 뒤 서재 관리자가 확인해야 합니다(이 작업에서는 catalog.json을 고치지 않았습니다). 루트 validate.py와 build_catalog.py --check는 등록 전이라 이 책을 대상으로 돌리지 않았습니다. MCP 2026-07-28, A2A 1.0, 제공자 도구 한도, 호스트 목록 예산 같은 시점 민감 정보는 원본 레슨 기준으로 썼고, 이후 팩트·출처 검수에서 공식 출처와 대조해 다른 부분을 고쳤습니다(검수 기록).
