지식자료와 운영 문서의 분리 · 2026-10-07

사용자 요청에 따라 서가에 있던 구축·분석·운영·기획 문서 13개를 지식자료 목록에서 모두 제외합니다. 문서 원본과 하단 운영 링크는 유지합니다. 앞으로 resources와 books에는 독자가 학습할 실제 지식자료만 등록합니다.

첫 책으로 AI Book · 직접 실험하는 AI 교과서를 등록합니다. 책 목록을 중앙 서가에 통합하여 검색·목록 보기·책 펼침을 적용합니다. 변경 대상은 카탈로그, 생성기, 메인페이지, 빈 목록 처리입니다. 자료가 없으면 준비 안내만 표시하고 검색·분류 도구는 숨깁니다. 생성 동기화, 내부 링크, 기존 단위 테스트로 확인합니다.

검증: Python 15개·JavaScript 4개 테스트 통과, HTML 15개 내부 링크·앵커 오류 0개. 공개 배포에서 학습 책 1개와 운영 문서 제외를 확인했습니다. 책 펼침·소개·목차와 키보드 Enter를 통한 책 읽기 이동을 확인했습니다.

첫 화면에서 할 수 있는 일

2026-10-07 요청에 따라 메인페이지와 GitHub Pages 배포를 구성했습니다. 공개 서재에서 분석 자료와 운영 기준, 기획서를 열 수 있습니다.

초기에는 운영 문서 13개를 배치했으나 지식자료가 아니므로 모두 제외했습니다. 실제 학습자료가 등록되면 검색·분류·목록 보기·책 펼침·동작 줄이기와 학습 책 목록을 제공합니다. 첫 책은 AI Book · 직접 실험하는 AI 교과서로 등록했습니다.

화면과 정보 구조

소개 → 유리 서가 → 학습 책 → 서재 소개 순서로 구성합니다. 기존 문서 주소와 주요 앵커를 유지했습니다. 맑은 색유리 책등에 아이보리 라벨과 명조체 제목을 배치합니다. 승인한 디자인 기준과 구현·검증 기록을 참고하세요.

자료 링크와 책 목록은 HTML에 미리 기록합니다. JavaScript를 끄더라도 문서를 열 수 있으며, JavaScript는 검색·분류·목록 보기와 책 미리보기, 선택한 책의 펼침 효과에 사용합니다. 검색은 현재 서재에 등록한 자료의 제목·설명·키워드를 대상으로 하며, 연결된 모든 책의 본문을 검색하지는 않습니다.

좁은 화면에서는 선반을 가로로 넘기고 펼친 책을 한 열로 읽습니다. 키보드 포커스, 본문 바로가기, 검색 결과 안내, 닫기와 Escape 복귀를 제공합니다. 실제 확인 범위는 검증 기록을 참고하세요.

서가 진열 규칙 · 2026-10-08

책이 늘어나도 서가가 가지런하고 아름답게 보이도록 정한 기준입니다. 새 책을 등록하거나 순서·색·분류를 바꿀 때 모든 작업자가 따릅니다. ✔ 표시는 생성기(scripts/build_catalog.py)가 오류로 막는 항목이고, 나머지는 사람이 화면에서 확인합니다.

  • 같은 크기와 각도: 모든 책등은 같은 높이·폭·기울기로 같은 바닥선 위에 실제 책처럼 1px 틈만 두고 붙어 섭니다. 책마다 높이를 다르게 하거나 일부만 기울이는 장식을 넣지 않습니다. 원근은 책등마다 같은 값(perspective(1100px) rotateY(-5deg))을 씁니다.
  • 색 ✔: color는 필수이며 유리 팔레트 여섯 색(aqua·blue·violet·sage·amber·rose) 중 하나입니다. 이웃한 두 책은 같은 색을 쓰지 않습니다. 팔레트 밖의 색을 쓰려면 먼저 디자인 기준에 색을 추가합니다.
  • 분류와 순서 ✔: spine_category는 필수이며 공백을 빼고 최대 4글자입니다(66px 책등에서 잘리지 않는 길이). 같은 분야는 같은 이름을 씁니다(예: 인공지능·컴퓨터·수학). 같은 분류의 책은 서로 붙여 세웁니다. 새 책은 같은 분류 묶음의 끝에, 새 분류는 서가 끝에 둡니다. 현재 순서는 인공지능 → 컴퓨터 → 수학입니다.
  • 책등 제목 ✔: 책등 제목 규칙을 따릅니다. 공백 제외 최대 6글자이며, 이웃 책과 무게가 비슷하도록 4~6글자를 권장합니다.
  • 서체: 책등 제목은 명조 토큰(--font-serif), 분류는 본문 토큰(--font-sans)만 사용합니다. 두 토큰은 assets/type.css에 있고 공통 글꼴 기준을 따릅니다. 책마다 글꼴을 따로 지정하지 않습니다.
  • 대표 삽화 ✔: 읽을 수 있는 책(published)은 펼쳤을 때 보일 대표 삽화 illustration이 있어야 합니다. 반복 주기는 3초 안팎을 권장합니다.
  • 선반 나눔: 한 단에 놓이는 책 수는 화면 폭이 정합니다. 선반 안쪽 폭에 책등(72px, 640px 이하 66px)과 1px 틈이 몇 개 들어가는지 세어, 한 단이 차면 아래에 새 선반 판을 놓고 이어서 세웁니다. 창 크기를 바꾸거나 검색으로 책이 줄면 다시 나눕니다(assets/shelves.js, 계산은 assets/shelf-model.mjs의 packShelves). 같은 분류 묶음이 한 단에 들어가면 쪼개지 않고 다음 단으로 옮기며, 한 단보다 긴 묶음(예: 20권 시리즈)만 남은 칸부터 채우고 아래 단으로 이어집니다. 그래서 단 끝에 빈 칸이 남을 수 있고, 이것은 의도한 모습입니다. 분류 이름은 마지막 선반 아래에 한 번만 둡니다. 목록 보기는 한 단으로 모읍니다. JavaScript가 없으면 생성기가 만든 12권 단위 선반이 가로로 넘겨 보는 대체 화면이 됩니다. 1440px에서는 한 단 15권, 1024px 11권, 768px 8권, 390px 4권, 320px 3권이 들어갑니다.
  • 등록 후 확인: 1280px·390px·320px 화면에서 선반이 몇 단으로 나뉘는지, 마지막 단 아래에 분류 이름이 있는지와 함께 책등 높이·폭·바닥선이 같은지, 제목과 분류가 잘리거나 겹치지 않는지, 이웃 색이 구분되는지 확인합니다.

책등 제목 규칙 · 2026-10-07

긴 제목이 라벨 안에서 잘리는 문제를 막기 위해 책등 이름을 별도로 편집합니다. 이 기준은 Codex와 Claude를 포함한 모든 작업자가 따릅니다.

  • 책등 명조체는 데스크톱·모바일 모두 최대 18px입니다. 제목 길이에 따라 글자를 늘리거나 임의로 축소하지 않습니다.
  • spine_title은 필수입니다. 내용을 정확히 나타내는 짧은 이름을 직접 작성하며, 공백을 제외하고 최대 6글자로 제한합니다. 한글 완성형·영문·숫자를 각각 한 글자로 셉니다.
  • 긴 제목을 앞에서부터 자르거나 말줄임표로 숨기지 않습니다. 기준을 넘으면 핵심 주제와 학습 활동을 살려 이름을 다시 씁니다.
  • 전체 제목은 title에 보존하고 목록·펼친 책·접근성 이름·검색에 사용합니다. 분류는 제목 아래에 표시합니다.
  • 등록 시 생성기가 누락·길이 초과·말줄임표를 오류로 알립니다. 배포 전에 320px 화면에서도 제목과 분류가 겹치지 않는지 확인합니다.

현재 책의 전체 제목은 “AI Book · 직접 실험하는 AI 교과서”, 책등 이름은 “AI 원리 실험”입니다. 신경망부터 언어 모델까지 원리를 실험으로 익힌다는 내용을 담았습니다.

수정 계획: 카탈로그·서가 생성기·책등 CSS·공통 지침·관련 문서를 함께 갱신합니다. 생성기의 경계값 검사와 실제 공개 화면의 글자 크기·잘림·전체 제목 보존을 확인합니다.

검증 완료: Python 17개·JavaScript 4개 테스트 통과, 내부 링크 오류 0개. 공개 Chrome의 320·390·768·1024px 프레임에서 제목 18px·잘림 0·분류 겹침 0을 확인했습니다. 목록과 펼친 책은 전체 제목을 표시합니다. 검증 수치와 실제 화면을 보관했습니다. 실제 모바일 기기 검사는 수행하지 않았습니다.

도서 통합 결정과 AI 책 이전 기록 · 책별 상세 기준은 books/주제/AGENTS.md에 둡니다.

책을 추가하고 공개하기

  1. 책 기획서로 대상 독자, 첫 질문, 계속 사용할 사례, 마지막 과제를 정합니다.
  2. data/catalog.json의 books에 책을 등록합니다. 고유한 id, 제목 title, 설명 description, 상태 status가 필요합니다.
  3. planned는 기획 중, writing은 집필 중, published는 읽을 수 있는 책입니다. 공개 상태에는 저장소 루트 기준 상대 주소(예: books/ai/) 또는 HTTPS 주소 url을 추가합니다.
  4. 아래 명령을 실행하고 카탈로그와 갱신된 메인페이지를 함께 커밋합니다. main에 반영되면 GitHub Pages가 자동 배포합니다.

아래는 입력 형식을 설명하기 위한 예시입니다. 실제 책 목록에 등록된 항목이 아닙니다.

{
  "id": "your-book-id",
  "title": "책의 전체 제목",
  "spine_title": "책등제목",
  "spine_category": "AI",
  "color": "aqua",
  "description": "어떤 질문을 풀고 무엇을 할 수 있게 되는지",

책등에는 필수 항목 spine_title(공백 제외 최대 6글자), 제목 아래에는 spine_category를 표시합니다. color는 필수이며 aqua·blue·violet·sage·amber·rose 중 하나입니다. 이웃 책과 겹치지 않게 고르고, 분류·순서는 서가 진열 규칙을 따릅니다. 책등 제목은 책등 제목 규칙에 따라 직접 다듬으며 자동으로 자르지 않습니다. 전체 제목은 목록과 미리보기에 남습니다.

실제 지식자료만 resources에서 관리합니다. 저장소 구축용 보고서·운영 기준·기획 양식은 여기에 등록하지 않습니다. category는 analysis·guide·template, keywords는 검색 키워드입니다. 프로젝트 안의 주소는 docs/문서.html처럼 상대 경로를 사용합니다.

서가 아래 큐레이션 · 2026-10-08

사용자 요청에 따라 서가 페이지 아래에 "질문 하나로 여러 책을 잇는 읽기 흐름"을 둡니다. 분야 지도와 읽기 경로를 나누는 원칙대로 두 부분으로 구성합니다.

  • 읽기 경로(learning_paths): 질문 하나, 대상 독자, 선수 지식, 출발 상황, 단계별 {책·장, 할 일, 시간, 이동 이유, 남길 기록}, 도전 과제, 점검 질문. 카드에는 거치는 책 순서와 총 시간을 자동으로 계산해 보여 줍니다. 현재 4개: AI는 왜 틀리는가 · AI는 내 문장을 어떻게 읽을까 · 판단하는 부품에서 배우는 층으로 · 내 노트북에서 모델이 돌아갈까.
  • 공통 개념(concepts): 영문 소문자 ID, 한국어 이름, 영문 동의어(aliases), 한 줄 요약, 등장하는 장 목록. 개념 이름과 동의어는 해당 책의 서가 검색어에도 더해져 "dot product"처럼 영어로 찾아도 책이 나옵니다. 모든 개념은 두 권 이상의 책에 걸쳐야 합니다.
  • 장 색인(chapter_index): 큐레이션이 가리킬 수 있는 장 주소와 "번호 · 장 제목". 경로나 개념이 색인에 없는 장, 또는 다른 책의 장을 가리키면 build_catalog.py가 실패합니다. 장 제목을 바꾸면 색인도 함께 고칩니다.

화면 표현(2026-10-08 개편): 사용자가 "쭉 나열하지 말고 세련되게"를 요청해 목록을 두 개의 그림으로 바꿨습니다. 읽기 경로는 노선도입니다. 위에서 질문을 고르면(탭, 좌우 화살표) 그 경로의 장들이 책 색깔의 정거장으로 이어지고, 정거장을 누르면 아래에 할 일·이동 이유·남길 기록이 나타납니다. 공통 개념은 지식 지도입니다. 네 권이 유리 책등으로 가장자리에 서고, 개념은 자기가 등장하는 책들의 무게중심에 놓입니다(scripts/atlas_renderer.py가 겹치지 않게 미리 계산한 SVG). 개념을 고르면 연결된 책으로 가는 선이 밝아지고 옆 카드에 만나는 장이 나옵니다. 720px 이하에서는 지도 글자가 너무 작아지므로 지도를 숨기고 개념 카드를 모두 펼칩니다. JavaScript가 없으면 모든 노선과 정거장, 개념 카드가 펼쳐진 채로 읽힙니다. 동작은 assets/curation.js, 모양은 assets/curation.css에 있습니다.

새 책이 들어올 때: 공개된 모든 책은 장 색인, 공통 개념 두 개 이상, 읽기 노선 하나 이상, 다른 책으로 나가는 링크와 들어오는 링크를 갖춰야 하며 validate.py가 이를 검사합니다(절차). 지도는 책 수에 맞춰 타원 위에 자동 배치됩니다.

렌더링은 scripts/curation_renderer.py가 맡습니다. 책 안에서 다른 책으로 가는 링크(../주제/#장ID)는 validate.py가 도착 책의 book-routes와 대조합니다. 새 경로를 더할 때는 각 단계의 할 일이 그 장의 실제 실험과 맞는지 책 본문에서 확인합니다.

한 저장소에서 책을 연결하는 기준

이 저장소는 책을 고르는 입구와 공통 집필 기준을 맡습니다. 각 책의 books/주제/ 폴더는 본문, 실험, 전용 자산, 테스트, 개발 문서를 관리합니다. 신규 도서는 이 저장소에 추가합니다. 책의 공개 주소가 정해지면 카탈로그에 등록하고, 각 책의 머리말에는 서가로 돌아가기 버튼을 둡니다.

다른 책으로 이동하는 링크에는 연결 이유를 씁니다. 독자가 다음 내용을 이해하는 데 필요한 선행 개념과 이어지는 질문을 함께 안내합니다. 여러 책을 묶는 학습 경로는 learning_paths에, 책을 가로지르는 공통 개념은 concepts에 정의하고 서가 아래 큐레이션 구역에 보여 줍니다. 문서의 제목·목차가 달라져도 생성기를 다시 실행합니다. 스타일이나 동작 모듈을 바꾸면 index.html의 자산 URL 버전도 갱신하여 배포 직후 캐시 혼용을 막습니다.

공개된 책의 주소를 바꿀 때에는 이 서재의 카탈로그와 해당 책의 복귀·관련 책 링크를 함께 점검합니다. 상세한 집필 원칙은 서재 운영 기준을 따릅니다.
