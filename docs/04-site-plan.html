서재 구성과 책 추가 방법

기준 문서를 탐색하고, 여러 저장소에서 자라는 학습 책을 한곳으로 연결합니다.

첫 화면에서 할 수 있는 일

2026-10-07 요청에 따라 메인페이지와 GitHub Pages 배포를 구성했습니다. 공개 서재에서 분석 자료와 운영 기준, 기획서를 열 수 있습니다.

자료 13개를 색유리 책등으로 배치하고, 검색·분류·목록 보기·책 펼침·동작 줄이기와 학습 책 목록을 제공합니다. 첫 책의 주제·독자는 아직 정하지 않았으므로 책 목록은 준비 상태로 표시합니다.

화면과 정보 구조

소개 → 유리 서가 → 학습 책 → 서재 소개 순서로 구성합니다. 기존 문서 주소와 주요 앵커를 유지했습니다. 맑은 색유리 책등에 아이보리 라벨과 명조체 제목을 배치합니다. 승인한 디자인 기준과 구현·검증 기록을 참고하세요.

자료 링크와 책 목록은 HTML에 미리 기록합니다. JavaScript를 끄더라도 문서를 열 수 있으며, JavaScript는 검색·분류·목록 보기와 책 미리보기, 선택한 책의 펼침 효과에 사용합니다. 검색은 현재 서재에 등록한 자료의 제목·설명·키워드를 대상으로 하며, 연결된 모든 책의 본문을 검색하지는 않습니다.

좁은 화면에서는 선반을 가로로 넘기고 펼친 책을 한 열로 읽습니다. 키보드 포커스, 본문 바로가기, 검색 결과 안내, 닫기와 Escape 복귀를 제공합니다. 실제 확인 범위는 검증 기록을 참고하세요.

책을 추가하고 공개하기

  1. 책 기획서로 대상 독자, 첫 질문, 계속 사용할 사례, 마지막 과제를 정합니다.
  2. data/catalog.json의 books에 책을 등록합니다. 고유한 id, 제목 title, 설명 description, 상태 status가 필요합니다.
  3. planned는 기획 중, writing은 집필 중, published는 읽을 수 있는 책입니다. 공개 상태에는 실제 HTTPS 주소 url을 추가합니다.
  4. 아래 명령을 실행하고 카탈로그와 갱신된 메인페이지를 함께 커밋합니다. main에 반영되면 GitHub Pages가 자동 배포합니다.
python3 scripts/build_catalog.py
python3 scripts/validate.py
python3 -m unittest discover -s tests -v
node --test tests/test_shelf_model.mjs

아래는 입력 형식을 설명하기 위한 예시입니다. 실제 책 목록에 등록된 항목이 아닙니다.

{
  "id": "your-book-id",
  "title": "책의 전체 제목",
  "spine_title": "책등제목",
  "spine_category": "AI",
  "color": "aqua",
  "description": "어떤 질문을 풀고 무엇을 할 수 있게 되는지",
  "status": "planned"
}

책등에는 spine_title(권장 4~6글자), 제목 아래에는 spine_category를 표시합니다. color는 aqua·blue·violet·sage·amber·rose 중 하나입니다. 생략하면 기본값을 사용하며 긴 제목은 책등에서 줄여 표시합니다. 전체 제목은 목록과 미리보기에 남습니다.

기존 자료는 resources에서 관리합니다. category는 analysis·guide·template, keywords는 검색 키워드입니다. 프로젝트 안의 주소는 docs/문서.html처럼 상대 경로를 사용합니다.

여러 저장소의 책을 연결하는 기준

이 저장소는 책을 고르는 입구와 공통 집필 기준을 맡습니다. 각 책의 저장소는 본문, 실험, 이전·다음 장 연결을 관리합니다. 책의 공개 주소가 정해지면 카탈로그에 등록하고, 각 책에는 나만의 서재로 돌아가기 링크를 둡니다.

다른 책으로 이동하는 링크에는 연결 이유를 씁니다. 독자가 다음 내용을 이해하는 데 필요한 선행 개념과 이어지는 질문을 함께 안내합니다. 여러 책을 묶는 학습 경로는 실제 책과 순서가 정해진 뒤 learning_paths에 정의합니다. 현재 메인페이지에는 학습 경로 화면을 구현하지 않았습니다. 문서의 제목·목차가 달라져도 생성기를 다시 실행합니다. 스타일이나 동작 모듈을 바꾸면 index.html의 자산 URL 버전도 갱신하여 배포 직후 캐시 혼용을 막습니다.

공개된 책의 주소를 바꿀 때에는 이 서재의 카탈로그와 해당 책의 복귀·관련 책 링크를 함께 점검합니다. 상세한 집필 원칙은 서재 운영 기준을 따릅니다.
