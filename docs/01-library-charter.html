OPERATING STANDARD / V1.0

내 서재의 집필·시각화 기준

학습자가 한 가지 문제를 이해하고, 직접 바꾸어 보고, 새로운 상황에서도 설명할 수 있게 만드는 것을 목표로 합니다.

대상: 책을 만들고 연결할 저자 · Codex · Claude   |   관찰과 제안을 구분하여 작성

01

책을 시작하기 전에 정할 것

첫 책의 주제는 아직 정하지 않았습니다. 주제별 백과사전부터 만들지 말고 독자 한 유형, 끝에 해결할 문제 하나, 계속 사용할 사례 하나를 먼저 고릅니다. 어떤 책을 먼저 만들지는 주제·대상 독자·학습 후 할 일을 함께 정한 뒤 결정합니다.

항목한 문장으로 남길 답
독자이미 아는 것과 어려워하는 것을 적는다.
끝의 행동독자가 설명·계산·비교·설계 중 무엇을 할 수 있어야 하는가?
공통 사례장마다 다시 등장하는 장치·사건·데이터·인물은 무엇인가?
범위다룰 모델과 이번 책에서 다루지 않을 복잡성은 무엇인가?
증거배웠는지 어떤 새 문제로 확인할 것인가?

책 기획서 양식을 복사해 시작합니다.

02

한 장이 다음 장을 필요로 하게 한다

장 순서는 용어의 목록이 아니라 해결 과정입니다. 각 장에 ①현재 문제 ②이전 장에서 확보한 결과 ③새로운 도구 ④해결한 부분 ⑤아직 남은 질문을 적습니다. 다음 장 링크의 문구에는 그 장을 읽어야 하는 이유를 담습니다.

예를 들어 센서 학습은 “빛이 있다”에서 시작해 “빛을 어떻게 전자로 바꾸는가”, “전자를 어떻게 세는가”, “숫자가 왜 흔들리는가”로 이어질 수 있습니다. 이 예시는 원문의 서사 구조를 분석한 것으로, 내 서재의 첫 책 주제가 확정되었다는 뜻은 아닙니다.

03

한 장의 기본 흐름

순서저자의 역할독자의 산출물
1. 문제관찰 가능한 현상과 이상한 점을 제시한다.현재의 설명 또는 예상
2. 예측변수를 바꾸기 전에 결과를 고르게 한다.한 문장 가설
3. 조작한 번에 한 핵심 변수를 바꾼다.기준값·변경값
4. 관찰그림과 수치의 변화를 함께 보여 준다.차이와 예외
5. 설명결과를 모델·수식·성립 조건으로 설명한다.원인 설명
6. 전이조건이 다른 새 문제와 다음 질문을 준다.새 상황의 판단

모든 장에 여섯 개의 큰 UI 상자를 넣으라는 뜻은 아닙니다. 읽기 흐름 속에서 각 역할이 빠지지 않게 합니다.

04

그림은 설명할 관계를 기준으로 고른다

설명할 것기본 표현필수 보완
순서·연결·경계SVG 흐름도·단면도라벨, 범례, 현재 단계
변수 간 관계2D 그래프·표단위, 축 범위, 기준선
시간에 따른 변화Canvas 애니메이션정지, 한 단계 진행, 재설정
공간 구조·가림·적층필요할 때만 3D고정 시점, 2D 대체 도식, 텍스트 요약
수치적 판단계산 모형·결과 표가정, 유효 범위, 실패 상태
소리의 구조파형·스펙트럼과 오디오사용자 재생, 정지, 음량, 청각 대체 설명

화려함보다 관찰 가능한 차이를 먼저 만듭니다. 색만으로 상태를 전달하지 않고 선 모양·문자·패턴을 함께 씁니다. 이동량·재생 시간·입자 개수가 현실과 다르면 축척 또는 개념 표현임을 밝힙니다.

05

실험 하나의 완료 조건

실험에는 질문, 입력과 단위, 유효 범위, 사용한 계산·데이터, 출력과 단위, 기준·경계 사례, 초기화, 결과를 읽는 문장이 있어야 합니다. 실제 계산·정해진 시나리오·시각적 비유 중 어떤 방식인지 명시합니다.

모델 계산과 화면 그리기를 분리합니다. 계산은 작은 대표값과 경계값으로 검사합니다. UI는 키보드·좁은 화면·재설정·오류 상태를 직접 확인합니다. 시뮬레이터를 실행할 수 없어도 핵심 주장과 예시 결과를 읽을 수 있어야 합니다.

06

책과 책의 연결 규칙

각 책은 같은 저장소의 books/주제/ 아래에서 독립 폴더로 관리합니다. 이 저장소는 서가·본문·학습 경로·공통 기준을 함께 관리하고 main/root에서 배포합니다. 서브모듈은 사용하지 않습니다.

연결규칙
장 내부안정적인 장 ID와 상대 경로를 쓴다. 파일 이동 시 기존 링크를 고려한다.
다른 책카탈로그에 등록한 책 경로를 기준으로 현재 문서에 맞는 상대 URL을 사용한다. 대상 장과 연결 이유를 함께 적는다.
허브로 복귀모든 책에 서재로 돌아가는 링크를 둔다.
GitHub Pages프로젝트 사이트의 /repo/ 하위 경로를 고려한다. /assets처럼 루트 고정 경로를 피한다.
학습 상태localStorage 키는 bookshelf:book-id:v1:progress처럼 책·버전을 포함한다.
카탈로그발행 상태·장 수·배포 주소는 하나의 manifest에서 관리한다. 초반에는 명시적으로 갱신하고 검사한다.

동일 계정의 기본 GitHub Pages 프로젝트 사이트는 같은 origin을 공유할 수 있으므로 저장 키가 충돌할 수 있습니다. 서로 다른 도메인 사이에 진행 상태가 자동 공유되는 것도 아닙니다. 처음에는 책별 로컬 저장만 사용합니다.

07

출처·최신성·오류를 관리한다

출처는 주장 가까이에 둡니다. 원리와 시점에 민감한 숫자를 구분하고, 산업·제도·제품 정보에는 기준일을 씁니다. 이미지·코드·데이터의 재사용 권한을 확인합니다. 원문의 콘텐츠나 브랜드를 그대로 복제하지 않습니다.

관찰과 제안, 구조 검사와 실제 동작 검사, 예측과 결과를 구분합니다. 오류를 발견하면 재현 절차와 영향 범위를 먼저 적고 고칩니다. 오래된 링크와 메타데이터를 정기 점검하되, 이번 작업에서 반복 자동화 일정은 만들지 않았습니다.

08

완성 판정과 첫 제작 범위

첫 제작은 완결된 한 장으로 시작합니다. 공통 사례가 이어지는 세 장으로 확장한 뒤 책 단위를 결정합니다. 독자에게 사전 질문·새 조건의 전이 문제를 주어 무엇을 배웠는지 확인합니다. 원 사이트의 규모나 실험 개수는 초기 목표가 아닙니다.

통과 기준확인 방법
서사장 앞뒤의 질문과 결과가 연결되는지 읽는다.
정확성모델·단위·가정·핵심 계산의 대표값을 확인한다.
사용성키보드, 작은 화면, 초기화, 대체 설명을 확인한다.
문서기획·출처·작업 이력·남은 문제가 HTML 허브에서 연결된다.
연결내부 파일·앵커·책 manifest 및 주요 외부 링크를 검사한다.
