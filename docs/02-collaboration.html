COLLABORATION / ONE SET OF RULES

Codex와 Claude의 공동 작업 방식

도구가 바뀌어도 의도·진행 상태·검증 결과가 저장소에 남도록 합니다.

대상: 책을 만들고 연결할 저자 · Codex · Claude   |   관찰과 제안을 구분하여 작성

01

모든 작업의 시작점

AGENTS.md를 공통 규칙의 원본으로 사용합니다. CLAUDE.md는 @AGENTS.md로 이 문서를 가져옵니다. Claude Code 버전·설정에 따라 실제 적용 방식이 달라질 수 있으므로 처음 작업할 때 규칙이 로드되었는지 확인합니다. 이 문서는 Claude에 저장소 권한을 부여하는 장치가 아닙니다.

작업 전에는 index.html, docs/00-intent.html, docs/01-library-charter.html, data/work-state.json을 읽고 현재 작업과 중복되지 않는지 확인합니다.

02

코드를 쓰기 전에 남길 결정

작업의 목적, 바꿀 파일, 독자에게 달라질 점, 확인 방법을 먼저 적습니다. 되돌릴 수 있는 작은 수정은 바로 진행합니다. 책의 범위·대상 독자·공통 모델을 바꾸는 결정은 변경 이유와 대안을 기록합니다. 사용자가 이미 승인한 범위의 구현 선택을 반복해서 확인받지 않습니다.

03

충돌 없이 작업한다

다른 도구로 넘기기 전 현재 변경을 작은 커밋으로 묶고 작업 트리를 확인합니다. 같은 파일을 동시에 고치지 않습니다. 병렬 작업이 필요하면 파일 소유 범위와 통합 순서를 먼저 정합니다. 담당자가 바뀌어도 상대의 미완료 변경을 임의로 초기화하거나 덮어쓰지 않습니다.

학습 내용과 모델·뷰를 분리하고 Python·JavaScript 함수는 100줄 이하를 기본으로 합니다. 반복 규칙이 확인되기 전에 범용 프레임워크를 만들지 않습니다. 문서용 정적 HTML·CSS와 작은 JavaScript부터 사용합니다.

04

인계할 때 남길 최소 정보

항목내용
완료독자 관점에서 달라진 동작과 변경 파일
근거참고 출처와 채택한 모델·가정
검증실행 명령·실제 결과·실행하지 않은 검사
남은 일구체적인 미완료 항목과 막힌 이유
다음 행동다음 담당자가 처음 할 한 가지 작업

짧은 기계 판독 상태는 data/work-state.json에, 자세한 결정과 인계 설명은 HTML 문서에 둡니다. 핵심 결정을 채팅 기록에만 남기지 않습니다.

05

검사는 위험에 맞춰 고른다

계산 함수는 정상값·경계값·불변 조건을 검사합니다. 링크와 manifest는 자동으로 검사합니다. 단순 문구·색상 수정에 구현을 복제하는 테스트를 추가하지 않습니다. 사용자에게 보이는 실험은 실제 브라우저에서 입력과 출력을 확인합니다.

검증하지 않은 내용을 “완료”로 적지 않습니다. 사이트의 링크가 열리는 것, 그래픽이 그려지는 것, 계산이 맞는 것, 학습 효과가 있는 것은 별개의 주장입니다.

06

규칙의 범위

공통 지침은 작업 맥락이며 실행 권한·보안 경계를 대신하지 않습니다. 민감한 데이터·인증 정보·개인 대화는 공개 저장소에 넣지 않습니다. 사용자가 요청하지 않은 메시지 전송이나 새 서비스 가입을 진행하지 않습니다.
